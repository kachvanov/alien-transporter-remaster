# 07. Windows-ноутбук: проверка LAN-игры (инструкция для Claude на этом ноутбуке)

Ты — Claude, работающий на Windows-ноутбуке. Хозяйка ноутбука помогает проверить сетевую игру (Alien Transporter Remaster,
Electron + Node) в паре со вторым компьютером — MacBook, который держит её партнёр. Ты делаешь всю техническую часть;
хозяйка нужна для кликов в игре и для согласований.

## Правила работы

- Работай **только** в папке проекта (ниже `C:\at`). Ничего не удаляй и не меняй вне неё.
- **Спрашивай хозяйку** перед: установкой любых программ, изменением профиля сети, правил Брандмауэра, любыми настройками системы.
  Сам эти настройки не меняй: объясни, что нужно сделать, и попроси подтверждения (или сделай вместе с ней через её клики).
- Не запускай ничего, что не описано здесь. Скрипты проекта в `tools\net\` безопасны (`windows-check.ps1` только читает).
- Пароли, ключи и личные данные тебе не нужны. Не ищи их.
- Игра локальная, наружу в интернет ничего не отправляет. Сеть — только локальная (Wi-Fi дома).
- Если что-то не получается дважды подряд — остановись, опиши, что видишь (команда + вывод), и спроси хозяйку.

## Что у тебя есть

- Архив проекта `at-win.zip` (хозяйка скажет, где он лежит; ~250 МБ). Внутри уже готовые ассеты — **Java, ffmpeg, SWF не нужны**.
- IP MacBook в Wi-Fi: **192.168.31.146** (порт игры 47020). Если выяснится, что адрес другой — спроси у хозяйки/партнёра.

## Шаг 1. Подготовка

1. Распакуй архив в `C:\at` (получится `C:\at\package.json`, `C:\at\assets\...`).
2. Проверь Node: `node -v`. Нужна версия 22 или новее. Если Node нет или версия старая — **спроси разрешение** хозяйки и установи
   LTS: `winget install OpenJS.NodeJS.LTS` (или скачай установщик с nodejs.org). После установки открой новый PowerShell.
3. В `C:\at`:
   ```powershell
   npm ci
   node node_modules/electron/install.js
   ```
   Вторая команда обязательна: Electron 44 не скачивает свой бинарь во время `npm ci`.
   Если `npm ci` упал из-за версии Node — попробуй Node 24 или 26 (на Маке стоит 26).
4. Проверка запуска: `npm run dev`. Должно открыться окно игры с меню. Закрой игру (Alt+F4 или крестик).
   Если игра пишет про отсутствующие файлы — сообщи, какие именно (возможно, нужна папка `build\` с Мака).

## Шаг 2. Сеть

1. Профиль сети Wi-Fi должен быть **Частный (Private)**. Проверь: `Get-NetConnectionProfile`. Если `Public` — объясни хозяйке и, с её
   согласия, поменяй: Параметры → Сеть и Интернет → Wi-Fi → свойства сети → Профиль сети → Частные
   (или `Set-NetConnectionProfile -InterfaceAlias "<имя>" -NetworkCategory Private` в PowerShell от администратора).
2. Диагностика (только чтение):
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\net\windows-check.ps1 -Peer 192.168.31.146
   ```
   Сохрани вывод. Запомни IPv4-адрес Wi-Fi-адаптера ноутбука (понадобится для проверки B).
   `TcpTestSucceeded : False` на этом этапе нормально, если Мак ещё не запустил Host.

## Шаг 3. Проверка A — хостит Мак, ноутбук = клиент

Попроси партнёра (он на Маке) запустить `npm run dev` → Online → Host game, нажать TEST и сказать тебе «хост готов».
Только после этого:

1. Без игры:
   ```powershell
   npx tsx tools/net/host-probe.ts 192.168.31.146
   ```
   Ожидаем `result : ok`, ~35 кадров/с, ping. **Запиши весь вывод.**
   Ошибки: `ETIMEDOUT`/`EHOSTUNREACH` → Мак не хостит, VPN/фаервол на Маке, или «изоляция клиентов» на роутере. `ECONNREFUSED` →
   хост не запущен. Скажи хозяйке, что передать партнёру.
2. В игре: `npm run dev` → Online → Join game. Хост должен появиться в списке за ≤ 2 с. **Запиши, появился ли и за сколько.**
   Если нет — введи адрес `192.168.31.146` вручную (это значит, что UDP-автопоиск блокируется; отметь в отчёте).
3. Попроси хозяйку и партнёра пройти уровень вдвоём: хозяйка летит газом (↑ ← →), корабль P2 должен появиться и управляться плавно.
   Спроси её, как на глаз: плавно / рывками / с задержкой. Нажми F3 в игре, чтобы показать отладку (если она открылась — перепиши
   значения сети).
4. Хозяйка нажимает **P** — у партнёра на хосте должна встать пауза **ровно один раз**; ещё раз P — пауза снимается.
5. Хозяйка закрывает окно игры посреди уровня — у партнёра должна появиться надпись «PLAYER 2 DISCONNECTED», игра продолжается.
   Потом подключается снова — P2 должен вернуться.

## Шаг 4. Проверка B — хостит ноутбук, Мак = клиент

1. Запусти `npm run dev` → Online → Host game. Экран покажет `<ip>:47020`.
2. Windows покажет окно Брандмауэра Защитника. **Это клик хозяйки:** галочка «Частные сети» + «Разрешить доступ».
   Попроси её, не нажимай вслепую. (Если окна не было — правило могло уже существовать или быть заблокировано: тогда
   Параметры → Безопасность Windows → Брандмауэр → «Разрешить работу с приложением» → Electron / Alien Transporter.)
3. Нажми кнопку **TEST** на экране Host: должно быть `OK`. Запиши, что показано (`OK n ADDRESSES` или `FAIL ...`).
4. Сообщи хозяйке IP ноутбука — она передаст партнёру. Партнёр на Маке выполнит `npx tsx tools/net/host-probe.ts <ip-ноутбука>`
   и сам подключится через Online → Join game. Спроси у хозяйки/партнёра результат (`result : ok`, кадры/с, ping, виден ли в списке за ≤ 2 с).
5. Повтори пункты 3–5 из шага 3 в обратную сторону (теперь партнёр — клиент): корабль P2 плавный? Пауза P у клиента = одна пауза на хосте?
   Уход клиента — «PLAYER 2 DISCONNECTED»? Хост выводит в консоль строку `[host] client left (...): avg … KB/s, peak … KB/s` — **перепиши её**.
