# T0.7 — Levels and models → JSON + overlay check

**Milestone:** M0 · **Depends on:** T0.4 (raw 1x export of `LevelNNPhysic_mc`) · **In parallel with:** T0.5, T0.6 · **Size:** M

## Goal
The `levels` step: `assets/data/levels/level01..20.json` and `assets/data/models.json` — exact placement data and component parameters. Overlay images and an autotest prove that the geometry matches the editor markup.

## Read before starting
- `docs/02-extraction-pipeline.md` (step 7 in full — it has the parameter schema and the expected numbers)
- `reference/as3/Level01Physic_mc.as` (what `__setProp` looks like), `reference/as3/Shuttle01Model_mc.as`
- Consumers: `reference/as3/ru/alientransporter/map/{LevelCore,ObjectManager,Factory,Ground}.as`, `reference/as3/ru/antkarlov/anthill/plugins/box2d/models/AntModelManager.as` — which clip properties they read (`x`, `y`, `rotation`, `width`, `height`, `scaleX`, `name`, `["alias"]`…)

## Steps
1. Load `placements.json` and `symbols.json` (types from T0.3). For level and model clips, sort the placements by `depth`.
2. Decompose the matrix using the formulas in `02` §7.2 and compute `width/height` per §7.3.
3. `__setProp` parser: use a regex to find the functions `__setProp___idN__<Clip>_<layer>_<k>()`, extract the assignments `this.__idN_.<prop> = <value>;`, parse the values (number, string, bool, array). Ignore the function with `componentInspectorSetting`.
4. Assemble the JSON per the schema in `02` §7.5. Objects with `cls = null` are skipped but counted.
5. zod schemas `LevelSchema`, `ModelsSchema` (discriminated by `cls`, with the required `props` from §7.6) in `src/engine/assets/schemas.ts`.
6. **Overlay.** For each level take the 1x raster of `LevelNNPhysic_mc` (from `build/extract/sprites/1x`, 800×600 crop by origin) and draw on top: GroundBox as semi-transparent red (rotated `width×height` rectangles centered at `x,y`), GroundCircle (circles with radius `width/2`), yellow for Station/Trigger/Sensor, blue for points (ShuttleSpawn, CoinPoint, SpawnPoint, KeyPoint). File `build/extract/debug/levelNN-overlay.png`. Draw via SVG → sharp.
7. **Match autotest.** For each GroundBox_com: the 1x raster pixel at `(x, y)` (with tolerance: at least one pixel within a 2 px radius) has the distinct green markup color. Determine the markup color from the raster (put it in the report). Choose the threshold so that all 609 boxes pass. If some do not pass, that is an extraction bug; investigate them rather than loosening the threshold.
8. Tests (`tools/extract/levels.test.ts`): 20 levels; for each level the number of objects of each class with an `instanceName` equals the number of `public var __idN_:<Class>` fields in the `.as`; the totals from `02` §7.7; all required parameters present; 33 models in `models.json`.

## Outputs
`tools/extract/{levels.ts,setprop.ts,flashMatrix.ts,levels.test.ts}`, `assets/data/levels/*.json`, `assets/data/models.json`, `build/extract/debug/level*-overlay.png`.

## Acceptance criteria
- [ ] All tests are green, including the match autotest for 609 GroundBox.
- [ ] In the report: 3 overlays (Level01, Level08, Level13) — file paths plus a conclusion that the geometry matches.
- [ ] `npm run check` is green. Commit `T0.7: levels and models`.

## Pitfalls
- `rotation` in Flash is in degrees, the Y axis points down, a positive angle is clockwise. `atan2(b, a)` gives exactly that.
- `GroundCircle_com`: radius = `width/2` (as in `Ground.makeCircleBody`). If `scaleX ≠ scaleY` it is an ellipse in the editor but a circle in the game. Log such cases.
- The `depth` order is critical: this is how the original creates bodies, and the physics depends on the body order.
