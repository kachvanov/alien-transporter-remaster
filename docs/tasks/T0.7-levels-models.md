# T0.7 — Уровни и модели → JSON + оверлей-проверка

**Милстоун:** M0 · **Зависит от:** T0.4 (сырой 1x-экспорт `LevelNNPhysic_mc`) · **Параллельно с:** T0.5, T0.6 · **Размер:** M

## Цель
Шаг `levels`: `assets/data/levels/level01..20.json` и `assets/data/models.json` — точные данные размещения и параметры компонентов. Оверлей-картинки и автотест доказывают, что геометрия совпадает с разметкой редактора.

## Прочитать перед началом
- `docs/02-extraction-pipeline.md` (шаг 7 целиком — там схема параметров и ожидаемые числа)
- `reference/as3/Level01Physic_mc.as` (как выглядят `__setProp`), `reference/as3/Shuttle01Model_mc.as`
- Потребители: `reference/as3/ru/alientransporter/map/{LevelCore,ObjectManager,Factory,Ground}.as`, `reference/as3/ru/antkarlov/anthill/plugins/box2d/models/AntModelManager.as` — какие свойства клипа они читают (`x`, `y`, `rotation`, `width`, `height`, `scaleX`, `name`, `["alias"]`…)

## Шаги
1. Загрузить `placements.json` и `symbols.json` (типы из T0.3). Для клипов уровней и моделей отсортировать размещения по `depth`.
2. Разложить матрицу по формулам `02` §7.2 и посчитать `width/height` по §7.3.
3. Парсер `__setProp`: регэкспом найти функции `__setProp___idN__<Clip>_<layer>_<k>()`, вытащить присваивания `this.__idN_.<prop> = <value>;`, разобрать значения (число, строка, bool, массив). Функцию с `componentInspectorSetting` игнорировать.
4. Собрать JSON по схеме `02` §7.5. Объекты с `cls = null` пропустить, но посчитать.
5. zod-схемы `LevelSchema`, `ModelsSchema` (с дискриминацией по `cls` и обязательными `props` из §7.6) в `src/engine/assets/schemas.ts`.
6. **Оверлей.** Для каждого уровня взять 1x-растр `LevelNNPhysic_mc` (из `build/extract/sprites/1x`, кроп 800×600 по origin) и нарисовать поверх полупрозрачным красным GroundBox (повёрнутые прямоугольники `width×height` с центром в `x,y`), GroundCircle (круги с радиусом `width/2`), жёлтым — Station/Trigger/Sensor, синим — точки (ShuttleSpawn, CoinPoint, SpawnPoint, KeyPoint). Файл `build/extract/debug/levelNN-overlay.png`. Рисовать через SVG → sharp.
7. **Автотест совпадения.** Для каждого GroundBox_com: пиксель 1x-растра в точке `(x, y)` (с допуском: хотя бы один пиксель в радиусе 2 px) имеет выраженный зелёный цвет разметки. Цвет разметки определить по растру (в отчёт). Порог подобрать так, чтобы все 609 боксов проходили. Если какие-то не проходят — это баг извлечения, их нужно разобрать, а не ослаблять порог.
8. Тесты (`tools/extract/levels.test.ts`): 20 уровней; по каждому уровню число объектов каждого класса с `instanceName` = числу полей `public var __idN_:<Class>` в `.as`; суммарные числа из `02` §7.7; все обязательные параметры на месте; 33 модели в `models.json`.

- [ ] В отчёте: 3 оверлея (Level01, Level08, Level13) — пути к файлам плюс вывод, что геометрия совпадает.

## Подводные камни
- `rotation` во Flash — градусы, ось Y вниз, положительный угол — по часовой стрелке. `atan2(b, a)` даёт именно это.
- `GroundCircle_com`: радиус = `width/2` (так в `Ground.makeCircleBody`). Если `scaleX ≠ scaleY` — это эллипс в редакторе, но в игре круг. Логировать такие случаи.
- Порядок по `depth` критичен: так оригинал создаёт тела, а от порядка тел зависит физика.
