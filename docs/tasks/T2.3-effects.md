# T2.3 — Particle effects (AntEffect*) + StaticEffect

**Milestone:** M2 · **Depends on:** M1, T0.6 · **In parallel with:** T2.1, T2.2, T2.4, T2.5 · **Size:** M (~1.1K lines of AS3)

## Goal
All of the original's effects (explosions, sparks, flashes, dust, snow, portal magic, stars) are reproduced from the `effects.json` data by the same emitter engine.

## Read before starting
- `reference/as3/ru/antkarlov/anthill/extensions/effects/*`: `AntEffectManager` (314), `AntEffectEmitter` (226), `AntEffectParticle` (163), `AntEffectProperty` (267), `AntEffectData` (88)
- `reference/data/effects.xml` and `assets/data/effects.json` (T0.6), `reference/as3/ru/alientransporter/states/PrepareState.as` (effect loading), `components/{StaticEffect,EffectInfo}.as`
- All effect calls in the game: grep `AntEffectManager|AntEffectEmitter|effects\.` over `reference/as3/ru/alientransporter`

## Steps
1. Port 1:1 into `src/engine/effects/`. Replace the XML parsing (E4X) with reading JSON per the `04` §5 convention (attributes are strings, conversion as in the AS3 code).
2. `AntEffectParticle` is an AntActor. Particle animations are symbols from the `CacheList` (present in the manifest).
3. `StaticEffect` (a level component, e.g. `SnowFall_eff` in Level01) and `StaticEffectNode` + handling in the corresponding system.
4. Remove all `STUB(T2.3)`.
5. Tests: the `SnowFall_eff` emitter over 35 ticks at a fixed seed creates the reference number of particles; a particle dies at `lifeTime`; `AntEffectProperty` with `lower/upper` ranges uses `AntMath` (deterministically).

## Outputs
`src/engine/effects/**`, system changes, tests.

## Acceptance criteria
- [ ] Level01 (snow), a barrel explosion (Level11), the portal (end of any level) visually match Ruffle (description and screenshots in the report).
- [ ] `npm run check` is green. Commit `T2.3: effects`.

## Pitfalls
- Check which effects depend on `G.gameData.fancyEffects` (in the original this is the "Effects" toggle in the pause menu).
