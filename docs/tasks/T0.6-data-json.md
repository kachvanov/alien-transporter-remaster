# T0.6 — Fonts, missions, texts, effects → JSON

**Milestone:** M0 · **Depends on:** T0.2 · **In parallel with:** T0.3–T0.5 · **Size:** M

## Goal
The `data` step: the original's XML data → JSON in `assets/data/` with zod schemas. Semantics and structure 1:1.

## Read before starting
- `docs/02-extraction-pipeline.md` (step 6), `docs/04-porting-guide.md` §5 (XML → JSON convention)
- `reference/data/*.xml`; consumers: `ru/alientransporter/fonts/Font.as`, `missions/MissionManager.as`, `missions/ContentManager.as`, `texts/Text.as`, `ru/antkarlov/anthill/extensions/effects/AntEffectManager.as`

## Steps
1. A universal `xmlToJson` converter (fast-xml-parser) per the `04` §5 convention: attributes → fields, repeated children → arrays, **all attributes stay strings** (the AS3 code does `Number()`/`int()` itself). Comments are dropped. Element order is preserved.
2. Fonts: `fontXX.xml` → `assets/data/fonts/fontXX.json` `{ name, charInterval, chars: [{ name, x, y, w, h }] }`. Here numbers are converted to number: this is our format, read by the port of `Font.as`. Characters commented out in the XML are not included.
3. `missions.xml` → `missions.json`, `texts_en.xml` → `texts.json`, `effects.xml` → `effects.json` (with the universal converter).
4. zod schemas in `src/engine/assets/schemas.ts`: `FontSchema`, `MissionsSchema`, `TextsSchema`, `EffectsSchema`. The schemas describe the actual structure: look at the XML first, then write the schema.
5. Tests: 10 fonts; `missions.json` has 19 `Mission` elements; `effects.json` has a `CacheList` and a list of effects, including `SnowFall_eff` (it is used in Level01 `StaticEffect_com`); all files validate against the schemas.

## Outputs
`tools/extract/{data.ts,xmlToJson.ts,data.test.ts}`, `assets/data/{fonts/*.json,missions.json,texts.json,effects.json}`, schemas.

## Acceptance criteria
- [ ] The tests from step 5 are green.
- [ ] In the report, for each XML, show a fragment of the source and of the result (5–10 lines).
- [ ] `npm run check` is green. Commit `T0.6: data json`.

## Pitfalls
- `effects.xml` has a `PropertiesList` referencing `effects.swf` — this is a leftover of the effects editor. The effect clips live in the main SWF (their list is the `CacheList`, which goes into the T0.4 whitelist).
- `Text_XmlTextEN` references text image symbols (`PauseTextEN_mc`, etc.) — they are also needed in the whitelist (check that T0.4 picks them up).
