# T3.6 — Online integration into the game: remote P2, client's ship, P2 leaving, pause

**Milestone:** M3 · **Depends on:** T3.2, T3.3, T3.4, T2.8 · **Size:** M

## Goal
A full two-player game over the LAN: the host is P1, the client is P2. P2 enters the level with their own throttle and flies their own ship in their own color; players leaving and returning are handled cleanly.

## Read before starting
- `docs/01-architecture.md` §8 (InputRouter), `docs/03-frame-and-network-protocol.md` §3–§5
- `reference/as3/ru/alientransporter/systems/UISystem.as` (P2 join, `isTwoPlayerMode`), `screens/GameScreen.as`, `map/Factory.as` (`makeShuttle`: `PlayerData` → ship appearance), `data/GameData.as`

## Steps
1. Session mode in the worker: `Solo | Host | Client`. In `Host`:
   - `InputRouter` ignores the local P2 keys (`Config.keyP2*`) and substitutes the remote bits for them (gas/left/right → P2 key "presses");
   - `pauseReq` → a one-tick press of `Config.keyPause1`.
2. **The client's ship.** `hello.ship` → a temporary `PlayerData` override for `Player2` for the duration of the session (not written to the host's save). After disconnecting — restore the original.
3. **The client disconnected:** if P2 is in the level — remove their shuttle by the same path the original uses when P2 leaves or dies with no lives left (find it in `UISystem`/`GameScreen`), without counting a death. Show a `NotifyView` "PLAYER 2 DISCONNECTED" (bitmap font). `isTwoPlayerMode` — by the original's rules.
4. **The client connected during a level** — P2 enters with throttle, like the local P2 in the original.
5. **The host left** (closed the window or "Stop") → `bye` → the client (T3.3) shows a message.
6. Check that all of the original's 2P logic (the portal waits for both, shared lives or coins — as in `GameData`) behaves online the same as locally.
7. Tests (headless): InputRouter in Host mode — remote bits turn into `isDown(keyP2Gas)`; a local W press is ignored; the `PlayerData` override does not end up in `save.json`.

## Outputs
Changes to `src/sim/InputRouter.ts`, `src/game/*` (minimal, with `DEVIATION: online`), `src/app/*`, tests.

## Acceptance criteria
- [ ] Two instances on a Mac: a full level for two, P2 joining, leaving and returning, pause from the client.
- [ ] `npm run check` is green. Commit `T3.6: online integration`.

## Pitfalls
- Do not write "network" code in the game's systems. The entire difference between the modes lives in `InputRouter` and in minimal hooks for connecting and disconnecting.
