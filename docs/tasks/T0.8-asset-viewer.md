# T0.8 — Dev Asset Viewer

**Milestone:** M0 · **Depends on:** T0.4, T0.7 · **In parallel with:** M1 (T1.1–T1.3) · **Size:** M

## Goal
`npm run viewer` opens a dev page in the browser (Vite + Pixi). On it you can view any animation from the manifest in any tier, played at 35 fps, and any level — three layers plus an overlay of objects from `levelNN.json`. This is the main visual asset-debugging tool for all subsequent tasks.

## Read before starting
- `docs/02-extraction-pipeline.md` §4.5 (manifest), §7 (levels)

## Steps
1. `tools/viewer/` (a separate Vite config; serves `assets/` as static files).
2. **Symbols** tab: a list of symbols with search. The selected symbol plays at 35 fps (play/pause/step buttons, tier selection 1x/2x/3x, zoom 1–4×). The registration point is a crosshair; the bounding box is a frame. Show `size1x`, `origin1x`, frame count.
3. **Contact sheet** tab: a grid of the first frames of all symbols in a group.
4. **Level** tab: level selection 01–20; Back/BG/FG layers (checkboxes), an object overlay by class (colors as in T0.7), a hover tooltip (`cls`, `alias`, props).
5. Use the same manifest zod schema as the engine (`src/engine/assets/schemas.ts`).

## Outputs
`tools/viewer/**`, the `viewer` script in `package.json`.

## Acceptance criteria
- [ ] `Coin_mc` rotates smoothly; the origin crosshair is at the center of the coin in all tiers.
- [ ] `Shuttle01Body_mc` (5 frames) and `PassengerBlue01Walk_mc` play without frame jitter (origin is stable).
- [ ] Level01: the layers line up with each other, the ground-object overlay sits on the rocks.
- [ ] Screenshots of these three checks are saved in `build/viewer-shots/` (paths in the report).
- [ ] `npm run check` is green. Commit `T0.8: asset viewer`.

## Pitfalls
- The viewer is a dev tool: it does not go into the production build and is not imported from `src/` (except the schemas).
