# T3.7 — Network tests, latency proxy, macOS and Windows permissions

**Milestone:** M3 (closing task) · **Depends on:** T3.6 · **Size:** S

## Goal
Prove that LAN play works in real conditions. Prepare everything for network permissions on both OSes.

## Read before starting
- `docs/05-verification.md` §8, `docs/03-frame-and-network-protocol.md` §8

## Steps
1. `tools/net/latency-proxy.ts`: a TCP proxy (`net`), parameters `--listen 47030 --target 127.0.0.1:47020 --delay 30 --jitter 15` (independently in both directions, byte order preserved).
2. Run the client through the proxy. Record in the report: the delay chosen by the jitter buffer, smoothness, input response time (from the F3 overlay: RTT + buffer delay).
3. `electron-builder.yml`: `mac.extendInfo.NSLocalNetworkUsageDescription` (text from `03` §8). Nothing for Windows, but describe the firewall permission in the README (T4.7).
4. A diagnostics screen in HostScreen: "Your addresses: …", "Port: 47020". The "TEST" button opens a local socket to its own address and port and shows OK/FAIL (a check that we listen on more than loopback).
5. The manual checklist `05` §8, items 1–6. Item 6 (Mac ↔ Windows) is done when the first Windows build is ready. If T4.6 is not ready yet — a dev run on Windows: `npm ci && npm run extract && npm run dev` (needs Java and ffmpeg) or a temporary build `electron-builder --win dir`.
6. Traffic measurement: average and peak KB/s host → client on Level11 for two (F3 overlay or a counter in `HostServer`).

## Outputs
`tools/net/latency-proxy.ts`, changes to `electron-builder.yml`, `HostScreen`, a report with the checklist results.

## Acceptance criteria (= M3 acceptance)
- [ ] The `05` §8 checklist is fully passed, results in the report.
- [ ] Traffic ≤ 500 KB/s; the client's input delay ≤ 100 ms on the LAN.
- [ ] `npm run check` is green. Commit `T3.7: network verification`.
