# T3.7 — Сетевые тесты, latency-proxy, разрешения macOS и Windows

**Милстоун:** M3 (завершающая) · **Зависит от:** T3.6 · **Размер:** S

## Цель
Доказать, что LAN-игра работает в реальных условиях. Подготовить всё для сетевых разрешений на обеих ОС.

## Прочитать перед началом
- `docs/05-verification.md` §8, `docs/03-frame-and-network-protocol.md` §8

## Шаги
1. `tools/net/latency-proxy.ts`: TCP-прокси (`net`), параметры `--listen 47030 --target 127.0.0.1:47020 --delay 30 --jitter 15` (независимо в обе стороны, порядок байт сохраняется).
2. Прогон клиента через прокси. Записать в отчёт: выбранную jitter-буфером задержку, плавность, время отклика на ввод (по F3-overlay: RTT + задержка буфера).
3. `electron-builder.yml`: `mac.extendInfo.NSLocalNetworkUsageDescription` (текст из `03` §8). Для Windows — ничего, но в README (T4.7) описать разрешение фаервола.
4. Экран диагностики в HostScreen: «Your addresses: …», «Port: 47020». Кнопка «TEST» открывает локальный сокет к своему адресу и порту и показывает OK/FAIL (проверка, что слушаем не только loopback).
5. Ручной чек-лист `05` §8, пункты 1–6. Пункт 6 (Mac ↔ Windows) выполняется, когда готова первая Windows-сборка. Если T4.6 ещё не готов — dev-запуск на Windows: `npm ci && npm run extract && npm run dev` (нужны Java и ffmpeg) или временная сборка `electron-builder --win dir`.
6. Замер трафика: средний и пиковый КБ/с хост → клиент на Level11 вдвоём (F3-overlay или счётчик в `HostServer`).

## Выходы
`tools/net/latency-proxy.ts`, правки `electron-builder.yml`, `HostScreen`, отчёт с результатами чек-листа.

## Критерии приёмки (= приёмка M3)
- [ ] Чек-лист `05` §8 пройден полностью, результаты — в отчёте.
- [ ] Трафик ≤ 500 КБ/с; задержка ввода клиента ≤ 100 мс на LAN.
- [ ] `npm run check` зелёный. Коммит `T3.7: network verification`.
