# T5.3 — Автоматическая локальная сборка dmg и exe после изменений

**Милстоун:** M5 · **Зависит от:** T4.5, T4.6 · **Размер:** S–M

## Цель
Пользователю надоело просить пересобрать сборки после каждого изменения. После любого слияния в `main`, которое меняет код игры, на этом Маке сама собирается актуальная пара сборок (macOS dmg arm64 и Windows Setup + portable x64) в `dist/`, без участия человека и без CI в облаке.

**Почему не GitHub Actions:** для сборки нужны ассеты оригинала (`assets/`, ~235 МБ, извлекаются из SWF). Репозиторий публичный, ассетов в нём нет и быть не должно (права автора оригинала, `CLAUDE.md`), а собранные приложения с его графикой нельзя публиковать (в том числе как артефакты Actions публичного репозитория). Решение пользователя (2026-10-05): локально на Маке. Не добавлять `.github/workflows/*` со сборкой.

## Прочитать перед началом
- `CLAUDE.md`, `docs/05-verification.md` §10 (сборки), `docs/tasks/T4.5-build-mac.md`, `T4.6-build-windows.md`
- `package.json` (скрипты `build:mac`, `build:win`), `electron-builder.yml`, `tools/build/*`

## Шаги
1. **`npm run dist:all`** — один запуск, который: проверяет, что есть `assets/` и `out/` пересобирается (`electron-vite build` один раз), собирает macOS dmg (arm64) и Windows NSIS Setup + portable (x64) электрон-билдером; складывает результат в `dist/`, имена содержат версию и короткий хэш коммита (через `BUILD_ID` и `artifactName` в `electron-builder.yml`); пишет `dist/BUILD-INFO.json` (коммит, дата, версия, размеры файлов, `ok`/`failed`, длительность каждого этапа). Падение одной платформы не должно стирать успешную сборку другой. Старые сборки: оставлять 2 последние пары, остальные удалять.
2. **Сборка из чистого состояния коммита**, а не из грязной рабочей копии: либо `git worktree`/`git archive` HEAD во временную папку с симлинками на `node_modules`/`assets`/`vendor`/`build`/`reference` (как в агентских worktree), либо отказ с понятной ошибкой, если дерево грязное. Обосновать выбор в отчёте.
3. **Git-хук `post-merge`** (в версионируемой папке `.githooks/`, включается `npm run hooks:install` = `git config core.hooksPath .githooks`): после слияния в `main` в основной копии (не в `.claude/worktrees/**`) запускает `dist:all` **в фоне, отвязанно** (`nohup`-стиль, хук возвращается сразу), с лог-файлом `dist/build.log`. Только если среди изменённых файлов (от последнего успешно собранного коммита до HEAD) есть `src/`, `electron/`, `resources/`, `package.json`, `package-lock.json`, `electron-builder.yml`, `index.html`, `electron.vite.config.ts` — на докомитах только в `docs/`, `tests/`, `tools/`, `.claude/` не собирать.
4. **Блокировка и перезапуск:** файл-замок (с PID, устаревший замок снимается); если сборка уже идёт и пришёл новый merge — после её окончания запускается ещё одна (а не параллельная), несколько merge подряд сливаются в одну дополнительную сборку.
5. **Уведомление macOS** по готовности/ошибке (`osascript display notification`: «Сборка <hash> готова: dmg + exe» / «Сборка упала: см. dist/build.log»).
6. **`npm run dist:status`** — печатает состояние: идёт ли сборка, последний успешный коммит и время, отстаёт ли `main` от последней сборки, пути к файлам.
7. Тесты: чистая логика (фильтр путей «нужна ли сборка», замок и очередь, имена файлов, ротация старых сборок, `BUILD-INFO`) — юнит-тесты без запуска electron-builder; реальный прогон `npm run dist:all` вручную в отчёте (команда и вывод, размеры файлов).
8. В `README.md` (раздел для разработчиков, если он есть; иначе в `docs/05` §10) — 5 строк: как включить хук и где лежат сборки. Корневой README пользовательский — не раздувать.

## Выходы
`tools/build/dist-all.ts` (+ вспомогательные модули), `.githooks/post-merge`, скрипты в `package.json` (`dist:all`, `dist:status`, `hooks:install`), `electron-builder.yml` (имена с хэшем), `docs/05` §10, тесты.

## Критерии приёмки
- [ ] `npm run dist:all` на Маке даёт в `dist/` dmg arm64, Setup и portable x64 с хэшем в имени и `BUILD-INFO.json`; сборка из чистого коммита.
- [ ] После `npm run hooks:install` merge с изменением в `src/` запускает фоновую сборку (проверено на тестовом merge в временной ветке), merge только документации — нет; хук возвращается за < 1 с.
- [ ] Два быстрых merge подряд = не более одной активной и одной отложенной сборки; замок не залипает после падения.
- [ ] Уведомление macOS приходит при успехе и при ошибке.
- [ ] Ничего не публикуется: никаких `git push`, `gh release`, загрузок; `.github/workflows` не создаётся; `dist/` в `.gitignore`.
- [ ] `npm run check` зелёный; коммит `T5.3: local auto builds`.

## Подводные камни
- Хук не должен ломать merge и не должен падать, если нет `assets/` (тогда просто сообщение в лог/уведомление).
- Хук срабатывает и в worktree агентов: пропускать пути с `/.claude/worktrees/`.
- Сборка тяжёлая (минуты, десятки гигабайт временных файлов) — не запускать параллельно с другой сборкой; нагрузку не вешать на сам `git merge`.
- Windows-сборка кросс-компилируется на Mac (T4.6): если нужен Rosetta/Wine — это уже настроено, не переделывать.
- Не трогать `docs/ROADMAP.md`, `docs/STATUS.md`, `.claude/**`: подключение хука к оркестратору делает оркестратор.
