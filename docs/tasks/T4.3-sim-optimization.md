# T4.3 — Оптимизация симуляции без изменения поведения

**Милстоун:** M4 · **Зависит от:** T4.1, T2.8 · **Размер:** M

## Цель
Выполнить требование пользователя «оптимизация физики, но физика такая же». Тик симуляции укладывается в бюджет на слабом Windows-ноутбуке (p95 ≤ 4 мс), при этом **все golden-хэши остаются прежними, бит в бит**.

## Прочитать перед началом
- `docs/05-verification.md` §4, §9; `docs/01-architecture.md` §3

## Шаги
1. **Профилирование.** `--perf-log=perf.json` (реализовать, если нет): раз в секунду FPS, p50/p95 времени тика и отдельно доли `plugins.update` (физика + системы), FrameWriter, ElementSimulation, AntLight. Сценарии Level11 и Level13 вдвоём, 60 с скриптового ввода. Chrome DevTools Performance для воркера.
2. **Разрешено:**
   - убрать аллокации в горячих путях игрового кода (переиспользуемые `b2Vec2`/`AntPoint`; без замыканий в цикле);
   - кеширование значений, которые гарантированно не меняются (например, метаданные кадров);
   - структуры данных в `ElementSimulation`/`PhysicalMap` (типизированные массивы, пулы) **при том же порядке арифметических операций** (порядок сложений float влияет на результат!);
   - FrameWriter без аллокаций.
3. **Запрещено:**
   - менять box2dweb, параметры `Step`, порядок систем, порядок создания объектов;
   - менять формулы или их порядок вычислений;
   - «приближённые» оптимизации.
4. После каждой оптимизации: `vitest run tests/golden` — хэши не изменились. Если изменились, оптимизацию откатить или переделать. Обновлять эталоны запрещено.
5. Отчёт: таблица «до/после» (p50/p95 тика, доли подсистем) на M5 и на Windows-ноутбуке (если доступен; иначе — на M5 с CPU throttling ×4 в DevTools как приближение).

## Выходы
Оптимизации в `src/**`, `--perf-log`, отчёт с цифрами.

## Критерии приёмки
- [ ] Все golden-реплеи зелёные без обновления эталонов.
- [ ] Бюджет тика из `05` §9 выполнен (или показано, что он уже выполнялся, и что конкретно улучшено).
- [ ] `npm run check` зелёный. Коммит `T4.3: sim optimization`.
