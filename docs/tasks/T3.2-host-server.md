# T3.2 — Host: ws server in main, worker ↔ main MessagePort bridge, heartbeat

**Milestone:** M3 · **Depends on:** T3.1, T1.7 · **In parallel with:** T3.3, T3.5 · **Size:** M

## Goal
The host accepts one client over WebSocket, checks the version, forwards simulation frames to it and passes its input to the worker. The renderer takes no part in this traffic.

## Read before starting
- `docs/01-architecture.md` §1 (the host's network path), §9; `docs/03-frame-and-network-protocol.md` §2–§5

## Steps
1. `electron/net/wsServer.ts` — a `HostServer` class **with no Electron dependencies**, so it can be tested in Node:
   - `start(port)`, `stop()`;
   - `onClientJoined(info)`, `onClientLeft(reason)`, `onInput(bits, seq)`, `sendFrame(buf)`;
   - a single slot: a second client gets `reject: full` and close 4000;
   - `buildHash` is compared (`reject: version`, 4001);
   - `ws.ping()` once per second, 5 s timeout;
   - `perMessageDeflate: false`;
   - if the socket cannot keep up (`bufferedAmount > 1 MB`), the frame is skipped — the queue does not build up.
2. `electron/main.ts`: IPC `net:hostStart/Stop`. On start a `MessageChannelMain` is created: `port1` stays in main (frames from the worker → `sendFrame`, client input → `port1.postMessage`), `port2` goes to the renderer (`webContents.postMessage('sim-port', null, [port2])`).
3. Preload: `ipcRenderer.on('sim-port', e => window.postMessage('sim-port', '*', e.ports))`. `src/app` catches the port and hands it to the worker (`worker.postMessage({t:'simPort'}, [port])`).
4. Worker: if there is a `simPort` and the mode is Host — after each tick, `simPort.postMessage(frame.slice(0))`. The copy is needed because the original goes to the renderer by transfer. Incoming `{bits, seq}` → `InputRouter.setRemote(bits)` (T1.6).
5. Host events (client connected or left, errors) → renderer (`net.onHostEvent`) → worker (for T3.6).
6. Tests (Node): start `HostServer`, connect a `ws` client → `welcome`; wrong `buildHash` → 4001; a second client → 4000; a frame arrives byte for byte; input arrives in `onInput` with `seq`; a "silent" client is disconnected on timeout (fake timers).

## Outputs
`electron/net/wsServer.ts`, changes to `electron/{main,preload}.ts`, `src/app/*`, `src/sim/worker.ts`, tests.

## Acceptance criteria
- [ ] The Node tests are green.
- [ ] Manually: `npm run dev` → the dev command "host start". `websocat ws://127.0.0.1:47020` (or a test script) receives binary frames at ~35/s after `hello`.
- [ ] `npm run check` is green. Commit `T3.2: host server`.

## Pitfalls
- `MessagePortMain` in main and `MessagePort` in the worker are different APIs (`port.on('message')` versus `onmessage`). Do not forget `port.start()` in main.
- Listen on `0.0.0.0`, otherwise another machine cannot connect.
