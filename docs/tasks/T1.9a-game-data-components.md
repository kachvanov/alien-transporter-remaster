# T1.9a — Порт данных игры: Config/G/Assets/Models, data/, components/, tags/, nodes/

**Милстоун:** M1 · **Зависит от:** T1.3, T1.4 · **Параллельно с:** T1.7, T1.8 · **Размер:** L (~3.7K строк AS3, почти всё — простые классы)

Все «данные» игры портированы: глобальные классы, данные игрока и уровней, 42 компонента, 4 тега, 31 Node. На этом фундаменте пишутся системы.

## Шаги
1. `src/game/Config.ts` — 1:1 (`FRAME_RATE = 35`, клавиши, `defLives = 3` и т.д.). `DEBUG_MODE = false`. Ключи клавиш — строки-имена как в оригинале.
2. `src/game/G.ts` — статический класс с `init(gameState)` как в оригинале. Внутри `G.init` порядок **строго** как в AS3: `core` → `physics.create()` → `models` → `levelManager` → `gameData` → `music` → `missions` → `content` → `plugins.add(core)` → `plugins.add(music)` → `Text.init()`. Ещё не портированные зависимости (LevelManager, MusicManager, MissionManager, ContentManager, Text) — заглушки-классы с `STUB(Txx)` и теми же публичными методами.
3. `Assets.ts` — список имён символов (строки вместо классов). `Models.ts` — регистрация моделей через `AntModelManager` (T1.4) по именам `*Model_mc` / `*Ragdoll_mc`.
4. `data/` — 1:1. Сохранение и загрузка (`saveData/loadData`) через `SaveStorage` (T1.6) вместо `AntCookie`; ключ `"alientransporter"`, формат — тот объект, что оригинал кладёт в SharedObject (`toObject/fromObject`).
5. `components/`, `tags/`, `nodes/` — 1:1. Node-классы получают `static components`. Компоненты, которые держат ссылки на view или модели (`Display`, `Physic`, `PhysicModel`, `Ragdoll`), типизируй через `import type`, чтобы не тянуть ещё не портированные модули.
6. `src/game/registry.ts` — реестр `className → constructor` для мест, где оригинал использует `getDefinitionByName` / `getQualifiedClassName` (собрать grep-ом по `reference/as3/ru/alientransporter`).
7. Тесты:
   - `GameData`: `resetData` → `saveData` → новый экземпляр `loadData` восстанавливает монеты, жизни, звёзды уровней и корабль игрока;
   - `LevelData.BONUS_LEVELS = [4,8,12,16,20]`;
   - `ShuttleStats`: расход топлива за тик в casual и hardcore (значения из формул AS3);
   - `Station.isInside` на граничных точках;
   - каждый Node создаётся через `AntCore.getNodes` для объекта с нужными компонентами (параметризованный тест по всем 31 Node).

## Выходы
`src/game/{Config,G,Assets,Models,AvailKeys,DebugSettings,Fonts,registry}.ts`, `src/game/{data,components,tags,nodes}/**`, тесты.

## Подводные камни
- `ShuttleStats` зависит от `G.gameData.casualMode` — это главный переключатель Casual/Hardcore. Не перепутай ветки.
- `Station` (262 строки) — самый «логичный» компонент, тестируй его тщательно.
- Поля `Number` без инициализации = NaN. Если где-то NaN «случайно работал» в оригинале, он должен так же работать и в порте.
