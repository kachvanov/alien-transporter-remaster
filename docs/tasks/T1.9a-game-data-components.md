# T1.9a — Port of game data: Config/G/Assets/Models, data/, components/, tags/, nodes/

**Milestone:** M1 · **Depends on:** T1.3, T1.4 · **In parallel with:** T1.7, T1.8 · **Size:** L (~3.7K lines of AS3, almost all simple classes)

## Goal
All of the game's "data" is ported: global classes, player and level data, 42 components, 4 tags, 31 Nodes. The systems are written on top of this foundation.

## Read before starting
- `docs/04-porting-guide.md` (all), `docs/tasks/T1.3-ecs-ants.md` (how to declare `static components` on a Node)
- `reference/as3/ru/alientransporter/`:
  - `Config` (52), `G` (120), `Assets` (17), `Models` (79), `AvailKeys` (61), `DebugSettings` (50), `Fonts` (68) — without the asset classes `Fonts_*`, `Sounds_*`, `Music_*`;
  - `data/*`: GameData (335), LevelData (67), PlayerData (95);
  - `components/*` (42 files, 2500 lines);
  - `tags/*` (48);
  - `nodes/*` (31 files, 692)

## Steps
1. `src/game/Config.ts` — 1:1 (`FRAME_RATE = 35`, keys, `defLives = 3`, etc.). `DEBUG_MODE = false`. Key values are string names as in the original.
2. `src/game/G.ts` — a static class with `init(gameState)` as in the original. Inside `G.init` the order is **strictly** as in AS3: `core` → `physics.create()` → `models` → `levelManager` → `gameData` → `music` → `missions` → `content` → `plugins.add(core)` → `plugins.add(music)` → `Text.init()`. Dependencies not yet ported (LevelManager, MusicManager, MissionManager, ContentManager, Text) are stub classes with `STUB(Txx)` and the same public methods.
3. `Assets.ts` — a list of symbol names (strings instead of classes). `Models.ts` — model registration via `AntModelManager` (T1.4) by the names `*Model_mc` / `*Ragdoll_mc`.
4. `data/` — 1:1. Saving and loading (`saveData/loadData`) go through `SaveStorage` (T1.6) instead of `AntCookie`; key `"alientransporter"`, format — the same object the original puts into the SharedObject (`toObject/fromObject`).
5. `components/`, `tags/`, `nodes/` — 1:1. Node classes get `static components`. Components that hold references to views or models (`Display`, `Physic`, `PhysicModel`, `Ragdoll`) are typed via `import type`, so as not to pull in modules that are not yet ported.
6. `src/game/registry.ts` — a `className → constructor` registry for places where the original uses `getDefinitionByName` / `getQualifiedClassName` (collect with grep over `reference/as3/ru/alientransporter`).
7. Tests:
   - `GameData`: `resetData` → `saveData` → a new instance's `loadData` restores coins, lives, level stars and the player's ship;
   - `LevelData.BONUS_LEVELS = [4,8,12,16,20]`;
   - `ShuttleStats`: fuel consumption per tick in casual and hardcore (values from the AS3 formulas);
   - `Station.isInside` at boundary points;
   - every Node is created via `AntCore.getNodes` for an object with the needed components (a parameterized test over all 31 Nodes).

## Outputs
`src/game/{Config,G,Assets,Models,AvailKeys,DebugSettings,Fonts,registry}.ts`, `src/game/{data,components,tags,nodes}/**`, tests.

## Acceptance criteria
- [ ] Every original file in the list has a port (the list parity check is in the report), headers in place.
- [ ] Int semantics checked with `int-report` for `ShuttleStats`, `Station`, `CargoHold`, `GameData`, `PlayerData`, `LevelData`.
- [ ] `npm run check` is green. Commit `T1.9a: game data and components`.

## Pitfalls
- `ShuttleStats` depends on `G.gameData.casualMode` — this is the main Casual/Hardcore switch. Do not mix up the branches.
- `Station` (262 lines) is the most "logic-heavy" component; test it thoroughly.
- `Number` fields without initialization = NaN. If somewhere NaN "accidentally worked" in the original, it must work the same way in the port.
