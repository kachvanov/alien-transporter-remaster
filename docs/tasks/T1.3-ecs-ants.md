# T1.3 — ECS "ants" (AntCore/AntFamily/AntNode/AntObject/AntSystem)

**Milestone:** M1 · **Depends on:** T1.1 · **In parallel with:** T1.2 · **Size:** M

## Goal
Port the ECS core on which all gameplay is built: objects with components, nodes (queries) over sets of components, and systems with an update order.

## Read before starting
- `reference/as3/ru/antkarlov/anthill/ants/*.as` (835 lines)
- Usage examples: `reference/as3/ru/alientransporter/nodes/ShuttleNode.as`, `systems/ShuttleSystem.as`, `states/GameState.as` (`addSystem`)

## Steps
1. Port `AntCore`, `AntFamily`, `IFamily`, `AntNode`, `AntNodeList`, `AntNodePool`, `AntObject`, `AntSystem` into `src/engine/ants/`.
2. Replacement for `describeType`. In the original, `AntFamily` uses reflection to discover the fields of the Node class and their component types. In TS, each Node class declares:
   ```ts
   export class ShuttleNode extends AntNode {
     static readonly components = { info: Info, display: Display, physic: Physic, stats: ShuttleStats } as const;
     info!: Info; display!: Display; physic!: Physic; stats!: ShuttleStats;
   }
   ```
   `AntFamily` reads `static components`. In the original (`AntFamily.as:39`) this is `describeType(nodeClass).factory.variable`: all variables except `object` (the reference to the AntObject) are stored in a `Dictionary` (Class → field name). Write the order as the order of `public var` in the Node's AS3 file. If the logic anywhere depends on iteration order, note it in the report.
3. `AntObject.add(component)`/`get(Class)`/`has(Class)`/`remove(Class)`: the key is the component's constructor, like a `Dictionary` keyed by `Class` in the original.
4. `AntCore` — an `IPlugin` (registered in `AntG.plugins`), `update()` with `_isLocked`, deferred additions and removals — as in the original. `eventUpdateComplete`.
5. Tests:
   - adding and removing objects updates the NodeList;
   - removing an object during a system's `update()` is handled the same way as in the original (deferred, if that is what the code does);
   - system order = `addSystem` order at equal priorities;
   - `getNodes(NodeClass)` returns the same `AntNodeList` every time.

## Outputs
`src/engine/ants/**`, tests.

## Acceptance criteria
- [ ] Tests are green; `npm run check` is green. Commit `T1.3: ecs ants`.

## Pitfalls
- The order of nodes in `AntNodeList` (appending to the end or the start) affects the processing order in systems, and therefore gameplay. Follow the original strictly.
- If `AntNodePool` reuses instances, do not reset fields "just in case" if the original does not do so.
