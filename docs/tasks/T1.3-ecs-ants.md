# T1.3 — ECS «ants» (AntCore/AntFamily/AntNode/AntObject/AntSystem)

**Милстоун:** M1 · **Зависит от:** T1.1 · **Параллельно с:** T1.2 · **Размер:** M

## Цель
Порт ECS-ядра, на котором построен весь геймплей: объекты с компонентами, узлы-выборки (Node) по наборам компонентов, системы с порядком обновления.

## Прочитать перед началом
- `reference/as3/ru/antkarlov/anthill/ants/*.as` (835 строк)
- Примеры использования: `reference/as3/ru/alientransporter/nodes/ShuttleNode.as`, `systems/ShuttleSystem.as`, `states/GameState.as` (`addSystem`)

## Шаги
1. Портировать `AntCore`, `AntFamily`, `IFamily`, `AntNode`, `AntNodeList`, `AntNodePool`, `AntObject`, `AntSystem` в `src/engine/ants/`.
2. Замена `describeType`. В оригинале `AntFamily` по рефлексии узнаёт поля Node-класса и их типы-компоненты. В TS каждый Node-класс объявляет:
   ```ts
   export class ShuttleNode extends AntNode {
     static readonly components = { info: Info, display: Display, physic: Physic, stats: ShuttleStats } as const;
     info!: Info; display!: Display; physic!: Physic; stats!: ShuttleStats;
   }
   ```
   `AntFamily` читает `static components`. В оригинале (`AntFamily.as:39`) это `describeType(nodeClass).factory.variable`: все переменные, кроме `object` (ссылки на AntObject), хранятся в `Dictionary` (Class → имя поля). Порядок описывай как порядок `public var` в AS3-файле Node. Если логика где-то зависит от порядка итерации — отметь в отчёте.
3. `AntObject.add(component)`/`get(Class)`/`has(Class)`/`remove(Class)`: ключ — конструктор компонента, как `Dictionary` по `Class` в оригинале.
4. `AntCore` — `IPlugin` (регистрируется в `AntG.plugins`), `update()` с `_isLocked`, отложенные добавления и удаления — как в оригинале. `eventUpdateComplete`.
5. Тесты:
   - добавление и удаление объектов обновляет NodeList;
   - удаление объекта во время `update()` системы обрабатывается так же, как в оригинале (отложенно, если так в коде);
   - порядок систем = порядок `addSystem` при равных приоритетах;
   - `getNodes(NodeClass)` возвращает один и тот же `AntNodeList`.

## Подводные камни
- Порядок узлов в `AntNodeList` (добавление в конец или начало) влияет на порядок обработки в системах, а значит на геймплей. Строго как в оригинале.
- Если `AntNodePool` переиспользует экземпляры, не сбрасывай поля «на всякий случай», если оригинал этого не делает.
