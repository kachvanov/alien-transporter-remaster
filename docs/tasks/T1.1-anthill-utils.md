# T1.1 — Утилиты Anthill: AntMath, geom, сигналы, плагины, AS3-хелперы

**Милстоун:** M1 · **Зависит от:** T0.1 · **Параллельно с:** M0 (T0.2–T0.8) · **Размер:** M

## Цель
Базовый слой `src/engine`, на котором стоит всё остальное: математика с детерминированным PRNG, точки и прямоугольники, сигналы, менеджер плагинов, таски и твины, хелперы семантики AS3. Плюс инструмент ревью `int-report`.

## Прочитать перед началом
- `docs/04-porting-guide.md` целиком (особенно §2 int-семантика, §3 замыкания, PRNG)
- `reference/as3/ru/antkarlov/anthill/{AntMath,AntPoint,AntRect,AntPluginManager}.as`, `utils/{AntColor,AntFormat,AntList,AntRating}.as`, `signals/*.as`, `plugins/{IPlugin,AntTaskManager,AntTween,AntTransition}.as`, `events/*.as`

## Шаги
1. `src/engine/utils/`:
   - `AntMath.ts` (1:1; PRNG по `04` §3 с `AntMath.seed(n)`);
   - `AntPoint.ts`, `AntRect.ts`, `AntColor.ts`, `AntFormat.ts`, `AntList.ts`, `AntRating.ts`;
   - `geom.ts` — минимальные `Point`/`Rectangle`/`Matrix` с той частью API `flash.geom`, которая используется в `reference/as3/ru/**` (собрать grep-ом);
   - `cast.ts` — `asType(v, C)`, `qualifiedName(obj)`;
   - `as3array.ts` — `sortAS3(arr, compareOrFlags)` и `sortOnAS3` — **точная копия алгоритма сортировки Flash Player** (avmplus, `core/ArrayClass.cpp`, `ArraySort::qsort` и вспомогательные функции; исходники: github.com/adobe/avmplus). Флаги `NUMERIC`, `DESCENDING`, `CASEINSENSITIVE`, `RETURNINDEXEDARRAY`, `UNIQUESORT`. Зачем: при равных ключах AVM2 переставляет элементы по-своему, а у всех систем игры `Priority = 0`, так что от этого алгоритма зависит порядок обновления систем (`04` §3). Тесты: массивы из 2–20 элементов с одинаковыми ключами и помеченными значениями — итоговый порядок совпадает с эталоном, посчитанным по алгоритму avmplus вручную или трассировкой (в отчёт — откуда эталон).
2. `src/engine/signals/`: `AntSignal`, `AntDeluxeSignal`, `AntSignalBinding`, `AntSignalBindingList` 1:1 (порядок вызова слушателей, `addOnce`, приоритеты — как в оригинале). Проверка типов аргументов в рантайме не нужна: типизация через дженерики `AntSignal<[A, B]>`.
3. `src/engine/events/`: `IEvent`, `IBubbleEventHandler`.
4. `src/engine/plugins/`: `IPlugin`, `AntPluginManager` (включая `sortHandler` и паузу), `AntTaskManager`, `AntTween`, `AntTransition` — 1:1. `AntG` пока не существует (появится в T1.2). Там, где плагины обращаются к `AntG.plugins`/`AntG.elapsed`, заведи временный модуль `src/engine/core/AntGStub.ts` с нужными полями; T1.2 заменит его настоящим `AntG`.
5. `tools/int-report.ts` (`npm run tool:int-report -- <file.as>`): печатает все объявления `:int`/`:uint` (поля, `var`, параметры, возвращаемые типы) с номерами строк.
6. Тесты:
   - AntMath: эталон 10 значений PRNG при сиде 12345 (снять с порта; для проверки корректности вручную посчитать первые 2 значения по формуле в комментарии теста), `randomRangeInt` в границах, `floor/round/lerp/angle` функции;
   - сигналы: порядок, `addOnce`, удаление во время dispatch;
   - AntTaskManager: последовательность задач на тиках;
   - AntTween: значение на половине длительности для `linear`, `easeIn/Out` — сравнить с формулами из AS3-кода.

## Выходы
`src/engine/{utils,signals,events,plugins}/**`, `tools/int-report.ts`, тесты.

## Критерии приёмки
- [ ] Каждый файл с шапкой `// Port of …`. Int-семантика соблюдена (сверено с `int-report`, в отчёте — список файлов, где были int-поля).
- [ ] Тесты зелёные; `npm run check` зелёный. Коммит `T1.1: anthill utils`.

## Подводные камни
- Сдвиги в PRNG: `>>> 0` после каждой операции, иначе JS уйдёт в отрицательные int32.
- Колбэки в сигналах сравниваются по ссылке. Проверь, что `remove` работает со стрелочными свойствами класса.
- `AntTween` в оригинале может регистрироваться в `AntG.plugins` сам. Сохрани это поведение, порядок плагинов важен (`01` §3).
