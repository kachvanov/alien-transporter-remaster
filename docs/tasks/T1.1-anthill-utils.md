# T1.1 — Anthill utilities: AntMath, geom, signals, plugins, AS3 helpers

**Milestone:** M1 · **Depends on:** T0.1 · **In parallel with:** M0 (T0.2–T0.8) · **Size:** M

## Goal
The base `src/engine` layer that everything else stands on: math with a deterministic PRNG, points and rectangles, signals, the plugin manager, tasks and tweens, AS3 semantics helpers. Plus the `int-report` review tool.

## Read before starting
- `docs/04-porting-guide.md` in full (especially §2 int semantics, §3 closures, PRNG)
- `reference/as3/ru/antkarlov/anthill/{AntMath,AntPoint,AntRect,AntPluginManager}.as`, `utils/{AntColor,AntFormat,AntList,AntRating}.as`, `signals/*.as`, `plugins/{IPlugin,AntTaskManager,AntTween,AntTransition}.as`, `events/*.as`

## Steps
1. `src/engine/utils/`:
   - `AntMath.ts` (1:1; PRNG per `04` §3 with `AntMath.seed(n)`);
   - `AntPoint.ts`, `AntRect.ts`, `AntColor.ts`, `AntFormat.ts`, `AntList.ts`, `AntRating.ts`;
   - `geom.ts` — minimal `Point`/`Rectangle`/`Matrix` with the part of the `flash.geom` API that is used in `reference/as3/ru/**` (collect it with grep);
   - `cast.ts` — `asType(v, C)`, `qualifiedName(obj)`;
   - `as3array.ts` — `sortAS3(arr, compareOrFlags)` and `sortOnAS3` — **an exact copy of the Flash Player sort algorithm** (avmplus, `core/ArrayClass.cpp`, `ArraySort::qsort` and helper functions; sources: github.com/adobe/avmplus). Flags `NUMERIC`, `DESCENDING`, `CASEINSENSITIVE`, `RETURNINDEXEDARRAY`, `UNIQUESORT`. Why: with equal keys AVM2 reorders elements in its own way, and all the game's systems have `Priority = 0`, so the system update order depends on this algorithm (`04` §3). Tests: arrays of 2–20 elements with identical keys and tagged values — the resulting order matches a reference computed by hand or by tracing the avmplus algorithm (say in the report where the reference comes from).
2. `src/engine/signals/`: `AntSignal`, `AntDeluxeSignal`, `AntSignalBinding`, `AntSignalBindingList` 1:1 (listener call order, `addOnce`, priorities — as in the original). Runtime argument type checking is not needed: typing via generics `AntSignal<[A, B]>`.
3. `src/engine/events/`: `IEvent`, `IBubbleEventHandler`.
4. `src/engine/plugins/`: `IPlugin`, `AntPluginManager` (including `sortHandler` and pause), `AntTaskManager`, `AntTween`, `AntTransition` — 1:1. `AntG` does not exist yet (it appears in T1.2). Where plugins access `AntG.plugins`/`AntG.elapsed`, create a temporary module `src/engine/core/AntGStub.ts` with the needed fields; T1.2 replaces it with the real `AntG`.
5. `tools/int-report.ts` (`npm run tool:int-report -- <file.as>`): prints all `:int`/`:uint` declarations (fields, `var`, parameters, return types) with line numbers.
6. Tests:
   - AntMath: a reference of 10 PRNG values at seed 12345 (taken from the port; to check correctness, compute the first 2 values by hand using the formula in the test comment), `randomRangeInt` within bounds, `floor/round/lerp/angle` functions;
   - signals: order, `addOnce`, removal during dispatch;
   - AntTaskManager: a sequence of tasks over ticks;
   - AntTween: value at half the duration for `linear`, `easeIn/Out` — compare against the formulas from the AS3 code.

## Outputs
`src/engine/{utils,signals,events,plugins}/**`, `tools/int-report.ts`, tests.

## Acceptance criteria
- [ ] Every file has a `// Port of …` header. Int semantics are respected (checked against `int-report`; the report lists the files that had int fields).
- [ ] Tests are green; `npm run check` is green. Commit `T1.1: anthill utils`.

## Pitfalls
- Shifts in the PRNG: `>>> 0` after every operation, otherwise JS goes into negative int32.
- Callbacks in signals are compared by reference. Check that `remove` works with arrow-function class properties.
- `AntTween` in the original may register itself in `AntG.plugins`. Preserve this behavior; plugin order matters (`01` §3).
