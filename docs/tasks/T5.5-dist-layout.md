# T5.5 — A tidy `dist/` layout for the local auto builds

**Milestone:** M5 · **Depends on:** T5.3 · **Size:** S

## Goal
After T5.3 `dist/` is a flat folder with hash-named files, a build log and state files, and the user keeps having to ask "where is the newest dmg?". Give `dist/` a layout in which the newest build is obvious, old builds do not pile up, and nothing is duplicated on disk.

## Read before starting
- `CLAUDE.md`, `docs/tasks/T5.3-local-auto-builds.md`, `docs/05-verification.md` §10
- `tools/build/dist-all.ts`, `dist-lib.ts`, `dist-env.ts`, `dist-status.ts`, `dist.test.ts`, `.githooks/post-merge`

## Target layout
```
dist/
  latest/                     the newest successful build, stable names (safe to bookmark / drag to Applications)
    Alien-Transporter-Remaster-mac-arm64.dmg
    Alien-Transporter-Remaster-win-setup.exe
    Alien-Transporter-Remaster-win-portable.exe
    BUILD-INFO.json           commit, date, version, per-file sizes (as now)
  archive/<date>-<hash>/      the previous build(s), original hash-named files + its BUILD-INFO.json
  build.log                   (rotated: keep the last ~1 MB)
  .state/                     .build-state.json, .build.lock and other internal files (hidden from the user's view)
```
A platform that failed in the newest build is simply absent from `latest/` and the failure is stated in `BUILD-INFO.json` (a platform that succeeded earlier is NOT carried over silently: `latest/` must never mix commits).

## Steps
1. Builds are produced into `dist/archive/<date>-<hash>/` with the hash-named files; `latest/` is then (re)filled with **hard links** to them under the stable names (fall back to copying if hard links fail). So nothing is stored twice. Update `latest/` atomically (build the new folder next to it and swap) so a user who opens the folder mid-build never sees a half-written set.
2. Rotation: keep `latest` plus the 1 previous build in `archive/`; remove older ones (and the files of a failed/partial build that never became `latest`). The existing T5.3 rotation of "2 newest builds" is replaced by this.
3. **Migration:** on the first run, loose files of the old flat layout (names produced by `dist:all`: `…-<hash>-arm64.dmg`, `… Setup <ver>-<hash>.exe`, `… <ver>-<hash>.exe`, `BUILD-INFO.json`, `.build-state.json`, `.build.lock`, `build.log`) are moved into the new places (the newest into `archive` + `latest`) or removed; files that do not match the patterns (the user's own) are never deleted.
4. `npm run dist:status` shows the new paths (`latest/…`) and the commit of `latest/`; new `npm run dist:open` opens `dist/latest/` in Finder (`open`), and does nothing harmful on a failed build.
5. The macOS notification text mentions `dist/latest`. `AT_NO_AUTOBUILD` and the hook behaviour stay as they are.
6. Tests (extend `tools/build/dist.test.ts`): layout creation with hard links (same inode), atomic swap, rotation, migration of an old flat folder (including that unknown files survive), a failed platform not mixing commits, status output. Real run: `npm run dist:all` once and show `ls -lR dist` (names, sizes) in the report.
7. Update the note in `docs/05` §10 (layout, `dist:open`). Do not touch the README (no Development section by the user's decision).

## Outputs
Changes in `tools/build/*`, `package.json` scripts (`dist:open`), `docs/05` §10, tests.

## Acceptance criteria
- [ ] After `npm run dist:all`, `dist/latest/` has the three files with the stable names plus `BUILD-INFO.json`; `dist/archive/` has the previous build only; nothing else loose in `dist/` except hidden state.
- [ ] `latest/` files are hard links of the archived ones (disk usage is not doubled; shown in the report).
- [ ] A second build keeps exactly one previous build in `archive/`; a third removes the oldest.
- [ ] Migration of the current flat `dist/` works and does not delete foreign files.
- [ ] The post-merge hook still returns in < 1 s and builds in the background; the lock/queue behaviour from T5.3 is unchanged.
- [ ] Nothing is published (no push, no release); `dist/` stays in `.gitignore`.
- [ ] `npm run check` green; commit `T5.5: dist layout`.

## Pitfalls
- Hard links only work on the same volume: `latest` and `archive` are both under `dist/`, so this holds; keep the copy fallback anyway.
- electron-builder temp outputs live in the tmp folder (T5.3 builds from a `git archive` snapshot): do not reintroduce `mac-arm64/`, `win-unpacked/`, `builder-debug.yml` into `dist/`.
- The user plays from the installed `/Applications` copy and copies `latest/` files to another machine: keep the names stable and free of spaces (use hyphens).
