# T3.5 — UDP auto-discovery of games on the LAN

**Milestone:** M3 · **Depends on:** T1.7 · **In parallel with:** M2, T3.2, T3.3 · **Size:** S

## Goal
The host appears in the second player's "Join" list on the same network within 2 seconds — like "LAN games" in Minecraft.

## Read before starting
- `docs/03-frame-and-network-protocol.md` §7, §8

## Steps
1. `electron/net/discovery.ts` (no Electron dependencies, testable in Node):
   - `startBeacon(info)` / `stopBeacon()` — JSON once per second to `255.255.255.255:47021` and to the broadcast address of each IPv4 interface (`os.networkInterfaces()`, excluding internal and link-local), `setBroadcast(true)`;
   - `startScan()` / `stopScan()` — bind `0.0.0.0:47021`, `reuseAddr: true`; parsing, filter `game === "AT-remaster"`, a list `{ip, hostName, port, status, buildHashMatches, lastSeen}`, TTL 3 s, an `update` event (no more than 4 times/s);
   - `getLocalIPv4()` — for HostScreen.
2. IPC in main and preload (`discovery.*`, `app.getLocalIPv4`), forwarding to the worker for the screens (T3.4).
3. Tests (Node): beacon and scan in one process on loopback (broadcast replaced by `127.0.0.1` via a parameter) — an entry appears and disappears by TTL; junk packets are ignored.

## Outputs
`electron/net/discovery.ts`, changes to `electron/{main,preload}.ts`, tests.

## Acceptance criteria
- [ ] Tests are green. Manually: two instances on one Mac see each other. On two machines on the same Wi-Fi — verified in T3.7.
- [ ] `npm run check` is green. Commit `T3.5: lan discovery`.

## Pitfalls
- macOS (15+) asks for "Local Network" permission on the first broadcast. In dev mode the request goes to Electron.app. `NSLocalNetworkUsageDescription` is added to the build in T4.5.
- If port 47021 is taken (a second instance on the same machine), `reuseAddr` should help. Otherwise — a clear error in the UI.
