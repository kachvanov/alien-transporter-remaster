# T3.5 — UDP-автопоиск игр в LAN

**Милстоун:** M3 · **Зависит от:** T1.7 · **Параллельно с:** M2, T3.2, T3.3 · **Размер:** S

## Цель
Хост виден в списке «Join» у второго игрока в той же сети в течение 2 секунд — как «игры в локальной сети» в Minecraft.

## Прочитать перед началом
- `docs/03-frame-and-network-protocol.md` §7, §8

## Шаги
1. `electron/net/discovery.ts` (без зависимостей от Electron, тестируется в Node):
   - `startBeacon(info)` / `stopBeacon()` — раз в 1 с JSON на `255.255.255.255:47021` и на broadcast-адрес каждого IPv4-интерфейса (`os.networkInterfaces()`, без internal и link-local), `setBroadcast(true)`;
   - `startScan()` / `stopScan()` — bind `0.0.0.0:47021`, `reuseAddr: true`; парсинг, фильтр `game === "AT-remaster"`, список `{ip, hostName, port, status, buildHashMatches, lastSeen}`, TTL 3 с, событие `update` (не чаще 4 раз/с);
   - `getLocalIPv4()` — для HostScreen.
2. IPC в main и preload (`discovery.*`, `app.getLocalIPv4`), проброс в воркер для экранов (T3.4).
3. Тесты (Node): beacon и scan в одном процессе на loopback (broadcast заменяется на `127.0.0.1` через параметр) — запись появляется и исчезает по TTL; мусорные пакеты игнорируются.

## Выходы
`electron/net/discovery.ts`, правки `electron/{main,preload}.ts`, тесты.

## Критерии приёмки
- [ ] Тесты зелёные. Вручную: два экземпляра на одном Маке видят друг друга. На двух машинах в одной Wi-Fi — проверяется в T3.7.
- [ ] `npm run check` зелёный. Коммит `T3.5: lan discovery`.

## Подводные камни
- macOS (15+) при первом broadcast спросит разрешение «Local Network». В dev-режиме запрос приходит на Electron.app. `NSLocalNetworkUsageDescription` добавляется в сборку в T4.5.
- Если порт 47021 занят (второй экземпляр на той же машине), `reuseAddr` должен помочь. Иначе — понятная ошибка в UI.
