# T4.2 — Сверка с оригиналом: визуальная (vs Ruffle) и поведенческая (в кадрах)

**Милстоун:** M4 · **Зависит от:** T2.8 · **Размер:** M

## Цель
Объективно показать, что ремастер выглядит и ведёт себя как оригинал, и исправить найденные расхождения.

## Прочитать перед началом
- `docs/05-verification.md` §5, §6
- Оригинал: `/Applications/Ruffle.app` + `/Applications/Flash Games/alien-transporter.swf`

## Шаги
1. **Эталоны из Ruffle.** Открыть SWF в Ruffle, окно 800×600 логических. Снять экраны из `05` §6 (`screencapture -l <windowId>` или вручную) → уменьшить до 800×600 (sharp lanczos3) → `tests/visual/reference/<scene>.png`. Если нужна помощь человека (пройти до экрана), попросить пользователя и описать шаги.
2. **Наши снимки:** `npm run shot -- --scene=<scene>` — скрытый запуск Electron, тир 1x, нужная сцена через dev-команды, `capturePage` 800×600 → `tests/visual/actual/`.
3. `tools/visual/compare.ts` — pixelmatch, `report.html` (эталон / наш / diff / %).
4. **Поведение:** таблица `05` §5. Оригинал — покадровый разбор записи экрана Ruffle; наш — dev-overlay или headless. Заполнить колонку «оригинал» в `docs/05-verification.md`.
5. Разбор расхождений: для каждого — причина (origin, blend, порядок слоёв, формула, int-семантика, порядок сортировки…) и исправление отдельным коммитом. Golden-эталоны обновляются только если исправление в порте (с обоснованием).

## Выходы
`tests/visual/reference/*.png`, `tools/visual/compare.ts`, `tests/visual/report.html`, заполненная таблица в `05`, исправления.

## Критерии приёмки
- [ ] Статические экраны ≤ 3% diff, уровни ≤ 6% (или каждое превышение объяснено).
- [ ] Поведенческие метрики в допусках `05` §5.
- [ ] `npm run check` зелёный. Коммиты `T4.2: …`.
