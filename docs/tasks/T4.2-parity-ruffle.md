# T4.2 — Parity check against the original: visual (vs Ruffle) and behavioral (in frames)

**Milestone:** M4 · **Depends on:** T2.8 · **Size:** M

## Goal
Objectively show that the remaster looks and behaves like the original, and fix any discrepancies found.

## Read before starting
- `docs/05-verification.md` §5, §6
- The original: `/Applications/Ruffle.app` + `/Applications/Flash Games/alien-transporter.swf`

## Steps
1. **References from Ruffle.** Open the SWF in Ruffle, 800×600 logical window. Capture the screens from `05` §6 (`screencapture -l <windowId>` or manually) → downscale to 800×600 (sharp lanczos3) → `tests/visual/reference/<scene>.png`. If human help is needed (to play through to a screen), ask the user and describe the steps.
2. **Our screenshots:** `npm run shot -- --scene=<scene>` — a hidden Electron launch, tier 1x, the needed scene via dev commands, `capturePage` 800×600 → `tests/visual/actual/`.
3. `tools/visual/compare.ts` — pixelmatch, `report.html` (reference / ours / diff / %).
4. **Behavior:** the table in `05` §5. The original — a frame-by-frame analysis of a Ruffle screen recording; ours — the dev overlay or headless. Fill in the "original" column in `docs/05-verification.md`.
5. Triage of discrepancies: for each one — the cause (origin, blend, layer order, formula, int semantics, sort order…) and the fix in a separate commit. Golden references are updated only if the fix is in the port (with justification).

## Outputs
`tests/visual/reference/*.png`, `tools/visual/compare.ts`, `tests/visual/report.html`, the filled-in table in `05`, fixes.

## Acceptance criteria
- [ ] Static screens ≤ 3% diff, levels ≤ 6% (or each excess is explained).
- [ ] Behavioral metrics are within the tolerances of `05` §5.
- [ ] `npm run check` is green. Commits `T4.2: …`.
