# T3.4 — Online screens (Host/Join, IP entry, discovered games)

**Milestone:** M3 · **Depends on:** T2.6, T3.5 · **Size:** M

## Goal
An "Online" button appears in the main menu. Through it you can host a game or join one — by IP or from the list of games discovered on the LAN. It looks like a native part of the original: the same backgrounds, buttons, bitmap fonts and sounds.

## Read before starting
- `reference/as3/ru/alientransporter/screens/{BasicScreen,MainMenuScreen,SelectLevelScreen}.as` (style, buttons, transitions), `ui/{ConfirmPopupView,KeyInputPopupView}.as`
- `docs/03-frame-and-network-protocol.md` §3, §7, §8

## Steps
1. The screens are **part of the simulation** (like the other screens), with buttons from `BtnBasic_mc` / `BtnGreen_mc`, etc. with Label captions. New screens that do not exist in the original are marked `// DEVIATION: online`.
2. **MainMenuScreen:** add an "ONLINE" button in a free spot of the button column (where a sponsor button was removed). If there is no room — under "PLAY" with a shift, coordinated with the visual balance (screenshot in the report).
3. **OnlineScreen:** "HOST GAME", "JOIN GAME", "BACK".
4. **HostScreen:**
   - the machine's IPv4 addresses and the port (from main via a worker message), status "WAITING FOR PLAYER…", then "PLAYER 2 CONNECTED: <name>";
   - buttons "START" (go to level selection, after which the game proceeds as usual) and "STOP";
   - the host starts the ws server and the UDP beacon when entering the screen and stops them on "STOP"/"BACK".
5. **JoinScreen:**
   - a list of discovered games (up to 5 rows: host name, IP, status, "different version" in gray), a click connects;
   - an address input field: a custom text input on Label, accepts digits, dot and colon, Backspace, Enter = Connect. Input comes from the worker keyboard: digit and dot codes exist in `AntKeyboard`;
   - buttons "CONNECT", "BACK"; the last address is filled in from the settings.
6. Connecting. Since the client does not run the simulation, JoinScreen sends a command to the renderer: `{t:'joinRequest', host, port}` → `src/app` stops the worker and starts `clientSession` (T3.3). On an error or a disconnect, the renderer restarts the worker and opens JoinScreen with a message ("Connection failed", "Host is full", "Different game version", "Connection lost").
7. Texts are in English, in the original's style (caps, the bitmap font `font04` or whichever similar screens use).

## Outputs
`src/game/screens/{OnlineScreen,HostScreen,JoinScreen}.ts`, `src/game/ui/TextInputView.ts`, changes to `MainMenuScreen`, `src/app/*`.

## Acceptance criteria
- [ ] The whole Host/Join flow works with mouse and keyboard on two instances on one Mac.
- [ ] Screenshots of the new screens next to the original screens (consistent style) are in the report.
- [ ] `npm run check` is green. Commit `T3.4: online screens`.

## Pitfalls
- Do not use HTML inputs over the canvas: the look must be native. The exception is if bitmap input cannot be made accessible; then discuss it in the report.
