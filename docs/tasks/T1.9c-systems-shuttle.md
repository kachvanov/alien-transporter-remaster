# T1.9c — Control/Shuttle/Health/Render/Station systems + ShuttleView

**Milestone:** M1 · **Depends on:** T1.9b · **In parallel with:** T1.9d · **Size:** L (~1.5K lines of AS3)

## Goal
The shuttle is controllable, flies by the original's physics, burns fuel, takes damage and refuels at fuel stations. The stations work. The shuttle and indicator views are drawn.

## Read before starting
- `docs/01-architecture.md` §3 (system order), `docs/04-porting-guide.md`
- `reference/as3/ru/alientransporter/systems/`: `ControlSystem` (43), `ShuttleSystem` (230), `HealthSystem` (82), `RenderSystem` (42), `StationSystem` (467), `Priority` (48)
- `views/`: `ShuttleView` (146), `IndicatorView` (71), `HouseView` (15)
- `ui/`: `FuelIndicatorView` (125) — if needed for the stations

## Steps
1. Port the systems 1:1 (they extend `AntSystem`). Registration in `GameState` is done in T1.9e, with **the `addSystem` calls in the same order as in the original** (`GameState.as:165–181`): Render, Control, Shuttle, Station, Passenger, Spawn, Ragdoll, Magnet, Health, Portal, Trigger, ObjectSpawn, UI, Menu, Sensor, Goal, Missile. The actual update order is then determined by the AVM2 sort (see Pitfalls).
2. `ControlSystem`: `KeyboardControl` reads `AntG.keys.isDown(keyName)` → `ShuttleControl`. Casual (auto-stabilization) and Hardcore — the logic is in `ShuttleSystem`/`ShuttleStats`, strictly per the original.
3. `ShuttleSystem`: thrust, strafe, steering, air resistance, `gravityResist`, fuel consumption, camera shake, engine fire (`fireSimulation.pour` → `STUB(T2.2)`), effects (`STUB(T2.3)`), sounds (`SndEngineGas` loop, etc. — already working from T1.8).
4. `HealthSystem`, `RenderSystem` (view ↔ body synchronization), `StationSystem` (landing, refueling, passengers at the station — interaction with PassengerSystem via components and signals; passengers are built by T1.9d, so this can be tested here without them).
5. `ShuttleView` (ship parts, hull and engine color, the passenger in the cabin, `color` on damage, `smoothing`), `IndicatorView`, `HouseView` — 1:1 on AntActor.
6. Tests (headless, Level01):
   - with no input the shuttle falls and settles on the ground, the ticks until touchdown are pinned to a reference;
   - full throttle for 35 ticks → climb height (reference);
   - full throttle until the tank is empty → number of ticks (reference);
   - the tank fills at a fuel station.
   The references are numbers produced by our port. In T4.2 they will be checked against the original (`05` §5).

## Pitfalls
- `ShuttleSystem` uses `G.physics.scale` and angle conversions (degrees ↔ radians). Carry every formula over without "simplifications".
- `Priority` in the original is static variables, all equal to 0. `AntCore.addSystem` calls `updatePriority()` → `_systems.sort(sortHandler)` after each addition, and `sortHandler` returns 0 on equality. The resulting system order comes from the AVM2 sort (`sortAS3` from T1.1) and **need not match the insertion order**. Print the resulting order in a test and pin it as a reference.
