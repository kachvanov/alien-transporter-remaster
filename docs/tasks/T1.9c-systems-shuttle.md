# T1.9c — Системы Control/Shuttle/Health/Render/Station + ShuttleView

**Милстоун:** M1 · **Зависит от:** T1.9b · **Параллельно с:** T1.9d · **Размер:** L (~1.5K строк AS3)

## Цель
Шаттл управляется, летает по физике оригинала, тратит топливо, получает урон, заправляется на топливных станциях. Станции работают. Виды шаттла и индикаторов рисуются.

## Шаги
1. Портировать системы 1:1 (наследуют `AntSystem`). Регистрация в `GameState` делается в T1.9e, **вызовы `addSystem` в том же порядке, что в оригинале** (`GameState.as:165–181`): Render, Control, Shuttle, Station, Passenger, Spawn, Ragdoll, Magnet, Health, Portal, Trigger, ObjectSpawn, UI, Menu, Sensor, Goal, Missile. Фактический порядок обновления потом определит AVM2-сортировка (см. подводные камни).
2. `ControlSystem`: `KeyboardControl` читает `AntG.keys.isDown(keyName)` → `ShuttleControl`. Casual (авто-стабилизация) и Hardcore — логика в `ShuttleSystem`/`ShuttleStats`, строго по оригиналу.
3. `ShuttleSystem`: тяга, стрейф, руление, сопротивление воздуха, `gravityResist`, расход топлива, тряска камеры, огонь двигателя (`fireSimulation.pour` → `STUB(T2.2)`), эффекты (`STUB(T2.3)`), звуки (`SndEngineGas` луп и т.д. — уже работают из T1.8).
4. `HealthSystem`, `RenderSystem` (синхронизация view ↔ тело), `StationSystem` (посадка, заправка, пассажиры на станции — взаимодействие с PassengerSystem через компоненты и сигналы; пассажиров делает T1.9d, здесь можно тестировать без них).
5. `ShuttleView` (части корабля, цвет корпуса и двигателя, пассажир в кабине, `color` при уроне, `smoothing`), `IndicatorView`, `HouseView` — 1:1 на AntActor.
6. Тесты (headless, Level01):
   - без ввода шаттл падает и ложится на землю, тиков до касания фиксируются эталоном;
   - полный газ 35 тиков → высота подъёма (эталон);
   - полный газ до пустого бака → число тиков (эталон);
   - на топливной станции бак заполняется.
   Эталоны — это числа, полученные нашим портом. В T4.2 их сверят с оригиналом (`05` §5).

## Подводные камни
- `ShuttleSystem` использует `G.physics.scale` и конверсии углов (градусы ↔ радианы). Каждую формулу переноси без «упрощений».
- `Priority` в оригинале — статические переменные, все равны 0. `AntCore.addSystem` после каждого добавления вызывает `updatePriority()` → `_systems.sort(sortHandler)`, а `sortHandler` при равенстве возвращает 0. Итоговый порядок систем даёт AVM2-сортировка (`sortAS3` из T1.1), и он **не обязан совпадать с порядком добавления**. Выведи получившийся порядок в тесте и зафиксируй эталоном.
