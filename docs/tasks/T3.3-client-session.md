# T3.3 — Клиент: WebSocket, jitter-буфер, ввод, обрывы, оверлей

**Милстоун:** M3 · **Зависит от:** T3.1, T1.7 · **Параллельно с:** T3.2, T3.5 · **Размер:** M

## Цель
Клиент подключается к хосту по IP, плавно показывает его кадры, отправляет свои нажатия и корректно переживает обрыв связи.

## Прочитать перед началом
- `docs/03-frame-and-network-protocol.md` §2–§6, `docs/01-architecture.md` §1, §5

## Шаги
1. `src/net/clientSession.ts` (renderer): `connect(host, port, hello)` → состояния `connecting → handshaking → playing → closed(reason)`, события для UI.
2. **Jitter-буфер** `src/net/JitterBuffer.ts` — чистая логика без DOM по `03` §6 (адаптивная задержка 1.5–3 тика, сброс при переполнении). `FramePlayer` (T1.7) в режиме клиента берёт кадры из буфера по «часам воспроизведения».
3. Звук: `AudioEngine.apply(frame)` вызывается, когда кадр становится текущим (oneShots не терять и не повторять — учитывать `tick`).
4. **Ввод:** `InputCollector` → биты (`gas/left/right` — объединение P1- и P2-раскладок из локальных настроек, `pauseReq` — фронт P) → `encodeInput` при изменении + heartbeat 35 Гц.
5. **Обрывы:** нет кадров 3 с или `close` → состояние `closed` с причиной → UI «Connection lost» → главное меню (сама навигация — в T3.4/T3.6).
6. **Esc у клиента** — локальный оверлей (рисует рендерер): «Disconnect? Yes / No». Yes → `{t:'bye'}` → close.
7. В режиме клиента локальный воркер не запускается (или останавливается).
8. Тесты: `JitterBuffer` на синтетических приходах (`05` §8); `clientSession` против `HostServer` из T3.2 в Node (с `ws` в роли `WebSocket` через инъекцию) — handshake, приём кадров, отправка ввода, реакция на `reject`.

## Выходы
`src/net/{clientSession,JitterBuffer}.ts`, правки `src/render/FramePlayer.ts`, `src/app/*`, `src/render/ClientOverlay.ts`, тесты.

## Критерии приёмки
- [ ] Тесты зелёные.
- [ ] Вручную: два экземпляра на одном Маке (`--profile=2`), клиент видит мир хоста плавно, его ввод двигает (пока тестовый) объект P2 (полная интеграция — T3.6).
- [ ] `npm run check` зелёный. Коммит `T3.3: client session`.

## Подводные камни
- `binaryType = 'arraybuffer'` обязательно.
- Не интерполируй через `sceneReset` — после смены экрана сразу показывай новый кадр.
