# T2.4 — Living lights: sensor beams, touches, alpha masks, rendering

**Milestone:** M2 · **Depends on:** M1, T0.4 (alpha masks) · **In parallel with:** T2.1–T2.3, T2.5 · **Size:** M (~660 lines of AS3 + rendering)

## Goal
The searchlight sensors work as in the original: beams stop at the shuttle's pixels, a beam touching the shuttle activates the sensor and the missiles, and the light is drawn with a radial gradient.

## Read before starting
- `docs/01-architecture.md` §5 ("Light"), `docs/02-extraction-pipeline.md` §4.4.1 (alpha masks), `docs/03-frame-and-network-protocol.md` §1 (ext LIGHT)
- `reference/as3/ru/antkarlov/anthill/extensions/livinglights/{AntLight(394),AntLightEnvironment(263)}.as`, `ru/alientransporter/views/SensorView.as` (198), `map/Factory.as:84` (`lightEnvironment.add(shuttleView)`)

## Steps
1. `src/engine/lights/AntLightEnvironment.ts`:
   - instead of `_backendBuffer` (BitmapData) — `isOpaque(x, y)`;
   - for each "opaque" child (and its children, in drawing order): inverse global transform of the point → frame-local coordinates → the bit of the current frame's alpha mask from `alphamasks.bin` (accounting for origin; outside the mask — transparent);
   - `true` if at least one object is opaque at that point;
   - `update()` / `updateLights` — 1:1.
2. `AntLight.ts` — 1:1. The logic from `draw()` (rays with `rayStep`/`angleStep`, polygon construction, `eventBeginTouch`/`eventEndTouch` with coordinates) runs at the render point (`01` §3). The result — a polygon, a gradient (`_colors`, `_alphas`, `_ratio`, matrix → center and radius), `blur`, `blend` for the `Frame` ext LIGHT.
3. `SensorView` — 1:1 (`colorIn`/`colorOut`, `alpha = 0.5`, `live`, steps, `updateInterval = 0.1`).
4. FrameWriter: an AntLight node → `texId = 0xFFFF`, `hasExt`, LIGHT payload.
5. Rendering `src/render/LightRenderer.ts`: `Graphics.poly(points).fill(FillGradient radial …)`, the node's blend, `BlurFilter` if `blur > 0`. Reuse `Graphics` by uid.
6. Remove `STUB(T2.4)` (including the temporary geometric test in SensorSystem).
7. Tests:
   - `isOpaque` for a shuttle at a known position: the center of the hull → true, a point outside → false, a pixel in a transparent "hole" of the frame → false;
   - the Level13 sensor beam stops at the shuttle, `eventBeginTouch` arrives on the expected tick during a scripted fly-in (reference).

## Outputs
`src/engine/lights/**`, `src/game/views/SensorView.ts`, `src/render/LightRenderer.ts`, FrameWriter changes, tests.

## Acceptance criteria
- [ ] Level13/Level14: the light cones look like Ruffle; when the shuttle flies into the beam the sensor turns red and the missiles fire (description and screenshots).
- [ ] `npm run check` is green. Commit `T2.4: living lights`.

## Pitfalls
- In the original, `isOpaque` takes `int` coordinates (camera pixels 800×600). Truncate with `|0`, as there.
- The shuttle is the only opaque object, but the implementation must be general (any AntActor in the environment).
