# T0.4 — Растеризация спрайтов, атласы, `manifest.json`, альфа-маски

**Милстоун:** M0 · **Зависит от:** T0.3 · **Параллельно с:** T0.5, T0.6 · **Размер:** L

## Цель
Шаг `sprites` превращает векторные символы SWF в атласы для тиров 1x/2x/3x и `assets/manifest.json` с точными регистрационными точками. Плюс альфа-маски для AntLight.

## Прочитать перед началом
- `docs/02-extraction-pipeline.md` (шаг 4 целиком, включая 4.4.1 и 4.5)
- `reference/as3/ru/alientransporter/Assets.as`, `views/ShuttleView.as`, `reference/data/effects.xml` (CacheList)

## Шаги
1. **Экспорт.** Для Z ∈ {1, 2, 3}: `-zoom Z -format sprite:png -export sprite build/extract/sprites/${Z}x` (кеш по хэшу SWF). На 2x это ~47 с, на 3x дольше — запускать параллельно тремя процессами Java.
2. **Whitelist/blacklist** строго по `02` §4.2 → `build/extract/whitelist.json`. Отчёт об отсутствующих и неучтённых символах.
3. **Origin.** Для каждого символа: `origin_Z = (−rectWithFilters.xMin·Z, −rectWithFilters.yMin·Z)`. Проверка: размер PNG = `ceil((xMax−xMin)·Z)` ±1 (иначе ошибка с именем символа). Эта формула проверена на всех 590 спрайтах.
4. **Слои уровней** `LevelNN{Back,BG,FG}_mc`: кроп области символа `[0,800)×[0,600)` → PNG `800Z×600Z`, origin `(0, 0)`, без trim.
5. **Trim и dedupe** остальных кадров (sharp `trim`/raw-буферы). Дедуп по sha1 RGBA внутри символа.
6. **Overrides** (`tools/extract/asset-overrides.json`, см. `02` §4.3).
7. **Группы** по `tools/extract/groups.json` (правила-регэкспы, первое совпадение побеждает) и **упаковка** maxrects (4096, padding 2, extrude 1). Выход `assets/gfx/{tier}/{group}-{n}.png`.
8. **Шрифты-картинки** (`reference/data/fonts/*.png`) кладутся в группу `ui` как символы `Font:<name>` (один кадр, origin 0,0), глифы потом режутся по JSON шрифта.
9. **manifest.json** по схеме `02` §4.5 + zod-схема в `src/engine/assets/schemas.ts` (её же использует движок). `texId` стабилен: сортировка символов по имени, кадры по порядку.
10. **Альфа-маски** (`02` §4.4.1): 1x, до trim, `alpha > 0`, для символов из `views/ShuttleView.as` и его детей (список собрать из кода и зафиксировать в `tools/extract/alphamask-symbols.json`).
11. **Сводка:** число символов, кадров и уникальных кадров, атласов по тирам и группам, Мпкс по тирам, топ-20 символов по площади.
12. Тесты `tools/extract/sprites.test.ts`:
    - у каждого символа whitelist есть кадры во всех тирах (с учётом `maxTier`);
    - blacklist отсутствует;
    - `Coin_mc` — 30 кадров, `origin1x ≈ (11.9, 11.95)`;
    - `MainMenuBG_mc#0` — size1x (800, 600), origin (0, 0);
    - `Level01BG_mc#0` в 2x имеет прямоугольник 1600×1200;
    - atlases на 2x для групп кроме `level-*` ≤ 4 (иначе тест выводит топ символов и падает).

## Выходы
`tools/extract/{sprites.ts,groups.json,asset-overrides.json,alphamask-symbols.json,sprites.test.ts}`, `assets/gfx/**`, `assets/manifest.json`, `assets/data/alphamasks.bin`, `src/engine/assets/schemas.ts` (manifest).

## Критерии приёмки
- [ ] Тесты из шага 12 зелёные.
- [ ] В отчёте приведена сводка из шага 11.
- [ ] Contact sheet `build/extract/debug/contact-2x.png` (по одному первому кадру каждого символа, с подписями) приложен к отчёту в виде пути; визуально нет пустых или обрезанных кадров.
- [ ] `npm run check` зелёный. Коммит `T0.4: sprites and atlases`.

## Подводные камни
- `AGIntro_mc` — 218 полноэкранных кадров (435 Мпкс на 2x). Он в blacklist: не трать на него время экспорта, если JPEXS позволяет выбрать символы (иначе просто пропусти при постобработке).
- JPEXS экспортирует **все** спрайты, включая безымянные вложенные клипы. Бери только папки, чей id есть в whitelist.
- Не делай premultiplied alpha в PNG. Pixi сам разберётся, нам нужен «прямой» альфа-канал, как в экспорте.
- Для 3x атласы могут не влезть в 4096 — это нормально, их будет больше. Проверь, что ни один кадр не превышает 4096 (иначе уменьши его тир через override).
