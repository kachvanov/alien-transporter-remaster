# T5.1 — Client in a network game: menu buttons look unavailable

**Milestone:** M5 (after M4, backlog) · **Depends on:** T3.6, T3.4 · **Size:** S

## Goal
In a network game the client sees the host's menu (the host's frames) and cannot press anything in it: the menu, the level and the garage are chosen by the host, and from the client only the throttle/left/right bits and the pause request go out (`docs/03`, T3.6; in the README: "the host picks a level, the client joins with throttle"). The client player does not know this and clicks on the buttons. After this task, at such moments the buttons on the client look **unavailable** (dimmed), and a hint says it is the host's turn.

## Read before starting
- `CLAUDE.md`, `docs/00-overview.md`, `docs/03-frame-and-network-protocol.md` (the sections on client input, frames, overlay), `docs/tasks/T3.3-client-session.md`, `T3.6-online-integration.md`
- `src/render/ClientOverlay.ts`, `ClientOverlayModel.ts`, `src/app/main.ts` (client mode)
- `reference/as3/` — how the original draws an inactive button (`AntButton`: state `enabled=false`/alpha), so that the look matches the game's style

## Steps
1. **Confirm the fact:** in client mode the mouse and the menu keys do not reach the host (if they somehow do, stop and describe it in the report: the task changes meaning).
2. Determine when the client is "only watching": the host is on the menu/selection/garage/between-levels screen (not in a level where the client controls their own ship). The source of the flag: a field in `Frame` (whether a `protocol` bump is needed — decide per `docs/03`; change `PROTO_VERSION`/buildHash deliberately) or an inference from the frame contents. Choose the minimal option and justify it in the report.
3. Show the unavailability on the client side (renderer/overlay, without touching the host's game): the menu buttons are dimmed (the original's inactive-button style), the cursor shows no hover/press, a hint in the bitmap font such as "WAITING FOR THE HOST" for the duration of the menu. Esc → "Disconnect?" remains.
4. During a level the view returns to normal as is; the pause buttons and the like are not affected, if per T3.6 they work on the client.
5. Tests: a model of the "client is only watching" flag (pure logic), e2e: the host in the menu → the client has the "unavailable" mode on (a `data-*` attribute), the host started a level → it is off. Look at the screenshot with your own eyes.
