# T1.5 — `Frame` format: writer, reader, uid, teleport

**Milestone:** M1 · **Depends on:** T1.2 · **In parallel with:** T1.4 · **Size:** M

## Goal
`src/frame`: serialization of the scene (AntEntity tree + sound + light) into a binary `Frame` strictly per `docs/03-frame-and-network-protocol.md` §1, and reading it back. This is the only contract between the simulation, the renderer and the network.

## Read before starting
- `docs/03-frame-and-network-protocol.md` §1 in full, `docs/01-architecture.md` §3–§5
- `reference/as3/ru/antkarlov/anthill/{AntEntity,AntActor,AntCamera}.as` — how the original draws: child traversal order, `visible/exists/onScreen`, applying `scrollFactor`, `origin`, `angle`, `scale`, `alpha`, `color`, `blend`

## Steps
1. `src/frame/constants.ts`: message types, flag bits, ext types, `MAX_NODES = 65535`.
2. `src/frame/types.ts`: `FrameData { tick, flags, musicTrack, musicVol, muteFlags, levelGroup, tickCost, nodes: NodeData[], oneShots, loops }`, `NodeData { uid, texId, flags, x, y, rotation, scaleX, scaleY, alpha, tint, ext? }`, `LightExt`, `DebugLinesExt`.
3. `src/frame/FrameReader.ts` — `readFrame(buf: ArrayBuffer): FrameData` with bounds checking and a clear `FrameDecodeError`.
4. `src/frame/FrameWriter.ts`:
   - A growing `ArrayBuffer` (reused between ticks, handed out as a `slice()` copy).
   - `write(scene: { root: AntEntity, camera: AntCamera, audio, lights, level, ... }) → ArrayBuffer`.
   - Walk the tree **in the original drawing order** (as `AntEntity.draw` → `drawChildren`). A node is written if `exists && visible` holds for it and its ancestors and the `AntActor` has a frame.
   - Screen coordinates: `global − camera.scroll × scrollFactor + shakeOffset`. Angle in radians. The resulting scale, alpha and color are as in `AntActor.drawActor`.
   - The sprite position = the frame's registration point (origin). The renderer sets the anchor from `origin1x`.
   - uid = `(entity.entityId << 8) | subIndex`. `entityId` is assigned in the AntBasic constructor (monotonic u24).
   - teleport — per the rules in `03` §1.
5. A "render point" hook in `Anthill.tick` (T1.2): FrameWriter is called between `state.postUpdate()` and `plugins.update()`.
6. Tests: round-trip (an empty frame, 1000 nodes with all flags, light with 100 points, debug lines); an error on a truncated buffer; node order = tree traversal order (a test tree of 3 levels); `exists=false` on a parent hides its children; teleport on `reset()`.

## Outputs
`src/frame/**`, tests.

## Acceptance criteria
- [ ] The byte format matches `03` §1 byte for byte (a test with a "golden" buffer for a small frame — a byte array in the test).
- [ ] Writing 600 nodes takes < 0.3 ms on an M5 (a microbenchmark in the test, soft threshold, log only).
- [ ] `npm run check` is green. Commit `T1.5: frame format`.

## Pitfalls
- `DataView` always with `littleEndian = true`.
- Do not create objects per node while writing (no allocations on the hot path).
