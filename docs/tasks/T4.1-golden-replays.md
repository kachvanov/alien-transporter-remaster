# T4.1 — Запись ввода и golden replays (детерминизм и «та же физика»)

**Милстоун:** M4 · **Зависит от:** T1.9e (начать можно сразу после M1 и расширять по мере M2) · **Размер:** M

## Цель
Набор реплеев, которые headless прогоняют уровни и сверяют хэши состояния мира с эталоном. Это страховка от регрессий и главный инструмент для T4.3: «оптимизировали, а физика та же».

## Прочитать перед началом
- `docs/05-verification.md` §4, `docs/01-architecture.md` §3 (детерминизм)

## Шаги
1. **Запись (dev):** F9 в игре → `{t:'cmd', name:'recordStart'}` в воркер. Воркер пишет `{ version, seed, level, casualMode, twoPlayers, ship, inputs: [[tick, ...flashKeyCodes], ...] }` (только тики, где набор клавиш изменился). Повторный F9 → сохранить через main в `tests/golden/replays/<level>-<timestamp>.json`.
2. **Скриптовые реплеи** `tests/golden/scripts/*.ts` — функции `(tick) => keysDown[]`. Минимум:
   - `idle-then-gas` для каждого из 20 уровней (10 с без ввода, 10 с газ);
   - `level01-deliver` (из T1.9d);
   - `level11-barrels`, `level13-sensor`.
3. **Прогон** `src/sim/headless.ts` → `runReplay(replay) → { hashes: string[], stats }`. Хэш каждые 35 тиков по `05` §4 (тела в порядке `GetBodyList()`, Float64 значения, ключевые числа игры).
4. `tests/golden/golden.test.ts` — для каждого реплея сверить с `tests/golden/expected/<name>.json`. При расхождении показать первый расходящийся блок тиков и diff ключевых чисел.
5. `npm run golden:update -- <name>|--all` — перезаписать эталоны (с явным подтверждением в выводе).
6. Проверка детерминизма: один реплей прогнать дважды в одном процессе и в двух разных процессах — хэши совпадают.

## Выходы
`src/sim/{headless,replay}.ts`, `tests/golden/{scripts,replays,expected}/**`, `tests/golden/golden.test.ts`, скрипт `golden:update`.

## Критерии приёмки
- [ ] ≥ 23 реплея (20 idle-then-gas + 3 сценарных), все зелёные; прогон всех ≤ 60 с на M5.
- [ ] Детерминизм подтверждён (шаг 6).
- [ ] `npm run check` зелёный (golden входит в vitest). Коммит `T4.1: golden replays`.

## Подводные камни
- Если реплеи «плавают» между прогонами — это баг детерминизма (Math.random, Date, порядок Map, неинициализированный NaN и т.п.). Найди и исправь, не ослабляй тест.
