# T4.1 — Input recording and golden replays (determinism and "the same physics")

**Milestone:** M4 · **Depends on:** T1.9e (can start right after M1 and be extended as M2 progresses) · **Size:** M

## Goal
A set of replays that run levels headless and compare world-state hashes against a reference. This is insurance against regressions and the main tool for T4.3: "we optimized it, and the physics is the same".

## Read before starting
- `docs/05-verification.md` §4, `docs/01-architecture.md` §3 (determinism)

## Steps
1. **Recording (dev):** F9 in the game → `{t:'cmd', name:'recordStart'}` to the worker. The worker writes `{ version, seed, level, casualMode, twoPlayers, ship, inputs: [[tick, ...flashKeyCodes], ...] }` (only ticks where the key set changed). A second F9 → save via main to `tests/golden/replays/<level>-<timestamp>.json`.
2. **Scripted replays** `tests/golden/scripts/*.ts` — functions `(tick) => keysDown[]`. At minimum:
   - `idle-then-gas` for each of the 20 levels (10 s with no input, 10 s of throttle);
   - `level01-deliver` (from T1.9d);
   - `level11-barrels`, `level13-sensor`.
3. **Run** `src/sim/headless.ts` → `runReplay(replay) → { hashes: string[], stats }`. A hash every 35 ticks per `05` §4 (bodies in `GetBodyList()` order, Float64 values, key game numbers).
4. `tests/golden/golden.test.ts` — for each replay, compare against `tests/golden/expected/<name>.json`. On a mismatch, show the first diverging block of ticks and a diff of the key numbers.
5. `npm run golden:update -- <name>|--all` — overwrite the references (with explicit confirmation in the output).
6. Determinism check: run one replay twice in the same process and in two different processes — the hashes match.

## Outputs
`src/sim/{headless,replay}.ts`, `tests/golden/{scripts,replays,expected}/**`, `tests/golden/golden.test.ts`, the `golden:update` script.

## Acceptance criteria
- [ ] ≥ 23 replays (20 idle-then-gas + 3 scenario ones), all green; running all of them takes ≤ 60 s on an M5.
- [ ] Determinism confirmed (step 6).
- [ ] `npm run check` is green (golden is part of vitest). Commit `T4.1: golden replays`.

## Pitfalls
- If replays "drift" between runs, it is a determinism bug (Math.random, Date, Map ordering, an uninitialized NaN, etc.). Find and fix it; do not weaken the test.
