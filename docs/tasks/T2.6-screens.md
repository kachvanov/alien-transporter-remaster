# T2.6 — screens/, PrepareState, transitions; without sponsor elements

**Milestone:** M2 · **Depends on:** T2.5 · **Size:** L (~2.7K lines of AS3)

## Goal
The complete game flow as in the original. Launch → PrepareState (preparation) → main menu → level selection → level → completion screen (stars, statistics) → next level. Plus the garage (ships, colors, key remapping, Casual/Hardcore), credits, restart.

## Read before starting
- `reference/as3/ru/alientransporter/screens/*`: `BasicScreen` (112), `MainMenuScreen` (76), `SelectLevelScreen` (413), `GameScreen` (310), `LevelCompleteScreen` (380), `RestartLevelScreen` (54), `GarageScreen` (618), `CreditsScreen` (66)
- `states/PrepareState.as` (207) — in the original it caches animations and effects with a progress indicator
- `ui/FadeEffectView.as`

## Steps
1. `PrepareState` — there is nothing to cache for us. Keep the initialization sequence (G.init, save loading, effect registration) and go straight to the menu. Ignore `AntG.frameRate = 28` (`04` §4). A loading screen is not needed, but if the original has a splash logo of the author (not of a sponsor) — keep it.
2. Screens — 1:1. Transitions via `FadeEffectView` (an ordinary animation, `01` §5).
3. **Remove the sponsor content**:
   - the buttons `BtnMoreGames_mc`, `BtnArmorGames_mc`, `BtnArmor_mc`, `BtnArmorLogoSmall_mc`, `BtnFaceBook_mc`, `BtnTwitter_mc`, `BtnPatreon_mc`;
   - the intro `AGIntro_mc`;
   - everything that calls the Armor Games API (achievements, etc.: grep `ArmorGames`/`agi`/`achievement` in `reference/as3`).
   Do not shift the layout of the remaining buttons (just do not create the removed ones). Mark each removal with `// DEVIATION: sponsor removed`. The button `BtnAchievements_mc`: if it leads to the sponsor's site — remove it; if to an internal screen — keep it.
4. **Credits** — keep. The author buttons (`BtnAnton_mc`, `BtnAhura_mc`, `BtnWesley_mc`) open links via `hostApi.openExternal` (domain whitelist — the URLs that are in the code). If a URL is dead, keep the button and disable the link (`DEVIATION`).
5. **GarageScreen**: ship and color selection, purchase with coins, P1/P2 key remapping (6 buttons, `KeyInputPopupView`), the Casual/Hardcore toggle — 1:1. The new keys are saved to the settings (T2.8), to `Config` for now.
6. `SelectLevelScreen`: 20 level buttons (bonus ones — `BtnLevelBonus_mc`), stars, locks.
7. The default start screen is the main menu. `--start-level` remains a dev flag.
8. Remove `STUB(T2.6)`.
9. e2e: menu → Play → select Level01 → the level is running → Esc/P → Main menu → Garage → change a color → Back.

## Outputs
`src/game/screens/**`, `src/game/states/PrepareState.ts`, e2e.

## Acceptance criteria
- [ ] The whole flow works with the mouse, as in the original. A comparison with Ruffle for every screen (screenshots in pairs) is in the report.
- [ ] There are no sponsor elements; the list of what was removed is in the report.
- [ ] `npm run check` and `npm run test:e2e` are green. Commit `T2.6: screens`.

## Pitfalls
- `GameScreen` contains the 2P logic (P2 blinkers, `removeBlinker("Player2")`). Do not lose it — the second player's join depends on it.
