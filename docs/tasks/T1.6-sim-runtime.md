# T1.6 — Sim runtime: 35 Hz GameLoop, worker, headless, SaveStorage, InputRouter

**Milestone:** M1 · **Depends on:** T1.2, T1.3, T1.5 · **In parallel with:** T1.4, T1.7 · **Size:** M

## Goal
The simulation runs in a Web Worker and in Node (headless) with the same code, ticks exactly 35 times per second, accepts input snapshots and emits a `Frame`. Saves go through an asynchronous interface.

## Read before starting
- `docs/01-architecture.md` §1, §3, §7, §8

## Steps
1. `src/sim/GameLoop.ts`:
   - `constructor(opts: { assets: AssetSource, save: SaveStorage, seed: number, host: HostApi })`;
   - `init()` — load `AssetRegistry`, `AntMath.seed(seed)`, create `Anthill` (T1.2). The initial game state is a test one for now: an empty scene; `GameState`/`PrepareState` appear in T1.9e;
   - `tick(input: InputSnapshot): ArrayBuffer` — one tick per `01` §3, returns a `Frame`;
   - `pump(nowMs)` — an accumulator, up to 3 ticks per call, the remainder is discarded.
2. `src/sim/worker.ts` — the message protocol with the renderer:
   - in: `{t:'init', seed, assetBase}`, `{t:'input', snapshot}`, `{t:'saveLoaded', key, data}`, `{t:'simPort'}` (MessagePort for networking, T3.2), `{t:'cmd', name, args}` (dev commands: `startLevel`, `setTimeScale`, `recordStart/Stop`);
   - out: `{t:'frame', buf}` (transfer), `{t:'save', key, data}`, `{t:'openExternal', url}`, `{t:'log', level, msg}`, `{t:'ready'}`;
   - loop: `setInterval(() => loop.pump(performance.now()), 4)`.
3. `src/sim/SaveStorage.ts` — the interface and `MemorySaveStorage` (for tests). `WorkerSaveStorage` (via renderer ↔ worker messages) with keys preloaded at `init`.
4. `src/sim/InputRouter.ts` — assembles the tick's final `InputSnapshot`: the local snapshot plus (in Host mode, T3.6) the remote P2 bits (`01` §8). Only the local path for now; the interface for remote input is ready.
5. `src/sim/headless.ts` — runs `GameLoop` in Node: `FsAssetSource`, `MemorySaveStorage`, runs N ticks with the given input, returns frames and hashes (for T4.1).
6. `src/app/SimClient.ts` (renderer): creates the worker, sends `init`, forwards input (from T1.7), receives frames and passes them to `FramePlayer` (T1.7), handles `save`/`openExternal` via `window.at`.
7. Tests: `GameLoop.pump` over 1000 ms of simulated time makes exactly 35 ticks; after a 500 ms "hang" it makes at most 3 ticks per call; a headless run of 100 ticks is deterministic (two runs with the same seed → identical frame buffers).

## Outputs
`src/sim/**`, `src/app/SimClient.ts`, tests.

## Acceptance criteria
- [ ] The tests from step 7 are green.
- [ ] `npm run dev`: the worker ticks, frames arrive in the renderer (a frames-per-second counter ≈ 35 in the console or overlay).
- [ ] `npm run check` is green. Commit `T1.6: sim runtime`.

## Pitfalls
- Do not use `requestAnimationFrame` in the worker — only `setInterval`/`performance.now()`.
- Pass the frame through `postMessage(msg, [buf])` (transfer), with no copying.
