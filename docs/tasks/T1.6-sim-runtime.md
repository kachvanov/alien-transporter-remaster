# T1.6 — Sim runtime: GameLoop 35 Гц, worker, headless, SaveStorage, InputRouter

**Милстоун:** M1 · **Зависит от:** T1.2, T1.3, T1.5 · **Параллельно с:** T1.4, T1.7 · **Размер:** M

## Цель
Симуляция запускается в Web Worker и в Node (headless) одним и тем же кодом, тикает ровно 35 раз в секунду, принимает снимки ввода и отдаёт `Frame`. Сохранения идут через асинхронный интерфейс.

## Прочитать перед началом
- `docs/01-architecture.md` §1, §3, §7, §8

## Шаги
1. `src/sim/GameLoop.ts`:
   - `constructor(opts: { assets: AssetSource, save: SaveStorage, seed: number, host: HostApi })`;
   - `init()` — загрузка `AssetRegistry`, `AntMath.seed(seed)`, создание `Anthill` (T1.2). Стартовое состояние игры пока тестовое: пустая сцена, в T1.9e появится `GameState`/`PrepareState`;
   - `tick(input: InputSnapshot): ArrayBuffer` — один тик по `01` §3, возвращает `Frame`;
   - `pump(nowMs)` — аккумулятор, до 3 тиков за вызов, остаток отбрасывается.
2. `src/sim/worker.ts` — протокол сообщений с renderer:
   - in: `{t:'init', seed, assetBase}`, `{t:'input', snapshot}`, `{t:'saveLoaded', key, data}`, `{t:'simPort'}` (MessagePort для сети, T3.2), `{t:'cmd', name, args}` (dev-команды: `startLevel`, `setTimeScale`, `recordStart/Stop`);
   - out: `{t:'frame', buf}` (transfer), `{t:'save', key, data}`, `{t:'openExternal', url}`, `{t:'log', level, msg}`, `{t:'ready'}`;
   - цикл: `setInterval(() => loop.pump(performance.now()), 4)`.
3. `src/sim/SaveStorage.ts` — интерфейс и `MemorySaveStorage` (для тестов). `WorkerSaveStorage` (через сообщения renderer ↔ worker) с предзагрузкой ключей при `init`.
4. `src/sim/InputRouter.ts` — собирает итоговый `InputSnapshot` тика: локальный снимок плюс (в режиме Host, T3.6) удалённые биты P2 (`01` §8). Пока только локальный путь, интерфейс под удалённый ввод готов.
5. `src/sim/headless.ts` — запуск `GameLoop` в Node: `FsAssetSource`, `MemorySaveStorage`, прогон N тиков с заданным вводом, возвращает кадры и хэши (для T4.1).
6. `src/app/SimClient.ts` (renderer): создаёт воркер, шлёт `init`, пересылает ввод (из T1.7), принимает кадры и отдаёт их в `FramePlayer` (T1.7), обрабатывает `save`/`openExternal` через `window.at`.
7. Тесты: `GameLoop.pump` за 1000 мс симулированного времени делает ровно 35 тиков; при «зависании» на 500 мс делает не больше 3 тиков за вызов; headless-прогон 100 тиков детерминирован (два прогона с одним сидом → идентичные буферы кадров).

## Выходы
`src/sim/**`, `src/app/SimClient.ts`, тесты.

## Критерии приёмки
- [ ] Тесты из шага 7 зелёные.
- [ ] `npm run dev`: воркер тикает, в renderer приходят кадры (счётчик кадров/с ≈ 35 в консоли или overlay).
- [ ] `npm run check` зелёный. Коммит `T1.6: sim runtime`.

## Подводные камни
- Не используй `requestAnimationFrame` в воркере — только `setInterval`/`performance.now()`.
- Кадр передавай через `postMessage(msg, [buf])` (transfer), без копирования.
