# T1.9b — Port of map/, levels/, models/: levels from JSON, factories, body models

**Milestone:** M1 · **Depends on:** T1.9a, T0.7 · **In parallel with:** — · **Size:** L (~3.5K lines of AS3)

## Goal
`LevelCore` loads a level from `assets/data/levels/levelNN.json` and creates the same objects, in the same order and through the same factories, as the original did when it walked the `LevelNNPhysic_mc` clip. The shuttle, passenger, rock, box, barrel and missile models are built from `models.json`.

## Read before starting
- `docs/04-porting-guide.md` §4 (ClipProxy), `docs/02-extraction-pipeline.md` §7 (level format)
- `reference/as3/ru/alientransporter/map/{LevelCore(276),ObjectManager(65),Factory(951),Ground(128)}.as`, `levels/*.as` (Level01..20 — empty subclasses + `LevelManager` 151), `models/*.as` (15 files, 1542 lines)

## Steps
1. `ClipProxy` (from T1.4) — a level object with a Flash-like API: `x, y, rotation, width, height, scaleX, scaleY, visible, name` + an indexer `proxy["alias"]` → `props.alias`. The `rotation` setter changes the field, but `width/height` stay "as at rotation = 0" — the way the original's factories behave (`param1.rotation = 0` → `width`).
2. `ObjectManager` 1:1: `add(classNames[], factoryFn)`, `createFrom(proxy)` by `proxy.cls` (instead of `getQualifiedClassName`).
3. `LevelCore` 1:1, with these replacements:
   - `create()`: three `AntTileMap`s (Back 0.25, BG 0.5, FG 1.0; `CELL_SIZE = 100`, 8×6) → `addClip("LevelNNBack_mc")`, etc.;
   - `startLoading()` → "caching" is instantaneous (`eventComplete` in turn, as in the original) → `createPhysicsFromClip(levelJson.objects)` in `depth` order → `Ground.create()` → `eventLoadingComplete.dispatch()`;
   - the list of `ObjectManager` registrations — exactly as in the original constructor (32 registrations: GroundBox_com → Ground.makeBoxBody, …, Tutorial_com → Factory.makeTutorial);
   - `clear()` / `destroyNodes()` — 1:1.
4. `Factory` (951 lines) — 1:1. All `make*` methods from the original's list. `param1: Sprite` → `ClipProxy`, `param1["prop"]` → proxied. `int` parameters are truncated (`makeShuttle(x:int, y:int, …)`).
5. `Ground` — 1:1 (`makeStopper`, `makeBoxBody`, `makeCircleBody`, `create`, `destroy`, `stopperList`, the static body).
6. `levels/Level01..20` — one shared `LevelCore` class with a level-number parameter (in the original the subclasses only set the clip classes). `LevelManager` — 1:1 (`register(1, "Level01", …)`).
7. `models/*` — 1:1 on top of `AntModelManager` (T1.4): `BasicModel`, `ShuttleModel`, `ShuttleRagdoll`, `PassengerModel`, `PassengerRagdoll`, `RockModel/Ragdoll`, `BoxModel/Ragdoll`, `BarrelModel/Ragdoll`, `MissileModel/Ragdoll`, `CollisionRule`.
8. The views that the factories create (`ShuttleView`, `PassengerView`, `RockView`, …) are done in T1.9c/T1.9d/T2.1. Minimal stub classes (an AntActor with `addAnimationFromCache` of the needed symbol) with `STUB(T1.9c)` etc. are enough here, if it cannot be built without them.
9. Tests (headless):
   - loading Level01 creates: 1 static ground body with 16 box and 18 circle fixtures, 2 stoppers, 2 Stations, 5 Triggers, 1 ExitPortal, 1 SpawnManager, 2 ShuttleSpawns, 3 Barrels;
   - creation order = `depth` order;
   - `ShuttleModel` for ship 1..4 creates bodies and joints, `getShapeAnimation("Body")` returns the symbol name;
   - loading all 20 levels in a row with `clear()` between them — no exceptions and no body leaks in `b2World`.

## Outputs
`src/game/{map,levels,models}/**`, tests.

## Pitfalls
- `Ground.body` is a single static body for all of the level's boxes and circles (fixtures accumulate, `create()` is called once). Fixture order = object order.
- `makeStopper` creates separate bodies. Repeat that.
- `LevelCore.clear()` does a lot of "cleanup" (joints in `layerMain`, `Ground.destroy`, smoke and fire simulations, effects, camera reset). Port it in full, with stubs for the parts that do not exist yet.
