# T1.9b — Порт map/, levels/, models/: уровни из JSON, фабрики, модели тел

**Милстоун:** M1 · **Зависит от:** T1.9a, T0.7 · **Параллельно с:** — · **Размер:** L (~3.5K строк AS3)

## Цель
`LevelCore` загружает уровень из `assets/data/levels/levelNN.json` и создаёт те же объекты, в том же порядке и через те же фабрики, что оригинал, когда обходил клип `LevelNNPhysic_mc`. Модели шаттла, пассажира, камней, ящиков, бочек и ракет строятся из `models.json`.

## Прочитать перед началом
- `docs/04-porting-guide.md` §4 (ClipProxy), `docs/02-extraction-pipeline.md` §7 (формат уровней)
- `reference/as3/ru/alientransporter/map/{LevelCore(276),ObjectManager(65),Factory(951),Ground(128)}.as`, `levels/*.as` (Level01..20 — пустые наследники + `LevelManager` 151), `models/*.as` (15 файлов, 1542 строки)

## Шаги
1. `ClipProxy` (из T1.4) — объект уровня с Flash-подобным API: `x, y, rotation, width, height, scaleX, scaleY, visible, name` + индексатор `proxy["alias"]` → `props.alias`. Сеттер `rotation` меняет поле, но `width/height` остаются «при rotation = 0» — как ведут себя фабрики оригинала (`param1.rotation = 0` → `width`).
2. `ObjectManager` 1:1: `add(classNames[], factoryFn)`, `createFrom(proxy)` по `proxy.cls` (вместо `getQualifiedClassName`).
3. `LevelCore` 1:1, с заменами:
   - `create()`: три `AntTileMap` (Back 0.25, BG 0.5, FG 1.0; `CELL_SIZE = 100`, 8×6) → `addClip("LevelNNBack_mc")` и т.д.;
   - `startLoading()` → «кеширование» мгновенное (`eventComplete` по очереди, как в оригинале) → `createPhysicsFromClip(levelJson.objects)` в порядке `depth` → `Ground.create()` → `eventLoadingComplete.dispatch()`;
   - список регистраций `ObjectManager` — ровно как в конструкторе оригинала (32 регистрации: GroundBox_com → Ground.makeBoxBody, …, Tutorial_com → Factory.makeTutorial);
   - `clear()` / `destroyNodes()` — 1:1.
4. `Factory` (951 строка) — 1:1. Все `make*` из списка оригинала. `param1: Sprite` → `ClipProxy`, `param1["prop"]` → проксирование. Параметры `int` приводить (`makeShuttle(x:int, y:int, …)`).
5. `Ground` — 1:1 (`makeStopper`, `makeBoxBody`, `makeCircleBody`, `create`, `destroy`, `stopperList`, статическое тело).
6. `levels/Level01..20` — один общий класс `LevelCore` с параметром номера (в оригинале наследники только задают классы клипов). `LevelManager` — 1:1 (`register(1, "Level01", …)`).
7. `models/*` — 1:1 поверх `AntModelManager` (T1.4): `BasicModel`, `ShuttleModel`, `ShuttleRagdoll`, `PassengerModel`, `PassengerRagdoll`, `RockModel/Ragdoll`, `BoxModel/Ragdoll`, `BarrelModel/Ragdoll`, `MissileModel/Ragdoll`, `CollisionRule`.
8. Views, которые создают фабрики (`ShuttleView`, `PassengerView`, `RockView`, …), делаются в T1.9c/T1.9d/T2.1. Здесь достаточно минимальных классов-заглушек (AntActor с `addAnimationFromCache` нужного символа) с `STUB(T1.9c)` и т.д., если без них не собрать.
9. Тесты (headless):
   - загрузка Level01 создаёт: 1 статическое тело земли с 16 box- и 18 circle-фикстурами, 2 stopper'а, 2 Station, 5 Trigger, 1 ExitPortal, 1 SpawnManager, 2 ShuttleSpawn, 3 Barrel;
   - порядок создания = порядок `depth`;
   - `ShuttleModel` для корабля 1..4 создаёт тела и суставы, `getShapeAnimation("Body")` возвращает имя символа;
   - загрузка всех 20 уровней подряд с `clear()` между ними — без исключений и без утечек тел в `b2World`.

## Подводные камни
- `Ground.body` — одно статическое тело на все боксы и круги уровня (фикстуры копятся, `create()` вызывается один раз). Порядок фикстур = порядок объектов.
- `makeStopper` создаёт отдельные тела. Повтори это.
- В `LevelCore.clear()` много «уборки» (joints в `layerMain`, `Ground.destroy`, симуляции дыма и огня, эффекты, сброс камеры). Портируй целиком, с заглушками для ещё не существующих частей.
