# T4.4 — Graphics tiers and memory budget (Windows 8 GB)

**Milestone:** M4 · **Depends on:** T2.8 · **Size:** S

## Goal
On a Windows laptop with 8 GB the application fits the memory budget and holds 60 FPS. On the Mac, maximum sharpness is used.

## Read before starting
- `docs/05-verification.md` §9, `docs/01-architecture.md` §5 (atlases and tiers)

## Steps
1. VRAM estimate: the sum of `w×h×4` over loaded atlases (+ mips, if enabled) → into the F3 overlay and `--perf-log`.
2. Per-platform packaging (`electron-builder` `extraResources` with filters): **mac** — `gfx/2x` + `gfx/3x` (+ `1x` as a fallback), **win** — `gfx/1x` + `gfx/2x`. Automatic tier selection takes into account what is in the build.
3. Unload the `level-NN` atlas when the level changes (check that textures are really freed: `texture.destroy(true)` + `source.unload()`).
4. Measure on both machines using the `05` §9 scenarios. If Windows does not fit:
   - first WebP atlases (the decoded memory is the same — this does not help VRAM);
   - then lazy `passengers`/`effects` groups;
   - then a tier override for the largest symbols.
   Compressed GPU textures (KTX2/Basis) — only if everything else has not helped, as a separate task.
5. Do not use the `--disable-gpu-compositing` flag or other Chromium hacks without need. If something is needed for Intel iGPUs on Windows — document it.

## Outputs
Changes to `electron-builder.yml`, `src/render/AtlasLoader.ts`, `PerfOverlay`, a report with measurements.

## Acceptance criteria
- [ ] The `05` §9 memory and FPS budgets are met on both machines (or the user's permission is obtained if the Windows laptop is unavailable for measurement — then measure on the Mac with tier 2x and carry over the conclusions).
- [ ] `npm run check` is green. Commit `T4.4: tiers and memory`.
