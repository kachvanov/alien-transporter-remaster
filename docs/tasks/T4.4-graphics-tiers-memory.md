# T4.4 — Тиры графики и бюджет памяти (Windows 8 ГБ)

**Милстоун:** M4 · **Зависит от:** T2.8 · **Размер:** S

## Цель
На Windows-ноутбуке с 8 ГБ приложение укладывается в бюджет памяти и держит 60 FPS. На Mac используется максимальная чёткость.

## Прочитать перед началом
- `docs/05-verification.md` §9, `docs/01-architecture.md` §5 (атласы и тиры)

## Шаги
1. Оценка VRAM: сумма `w×h×4` загруженных атласов (+ mip, если включены) → в F3-overlay и `--perf-log`.
2. Упаковка по платформам (`electron-builder` `extraResources` с фильтрами): **mac** — `gfx/2x` + `gfx/3x` (+ `1x` для fallback), **win** — `gfx/1x` + `gfx/2x`. Авто-выбор тира учитывает, что есть в сборке.
3. Выгрузка атласа `level-NN` при смене уровня (проверить, что текстуры реально освобождаются: `texture.destroy(true)` + `source.unload()`).
4. Замер на обоих машинах по сценариям `05` §9. Если Windows не укладывается:
   - сначала WebP-атласы (декодированная память та же — это не помогает VRAM);
   - потом ленивые группы `passengers`/`effects`;
   - потом override тира для самых больших символов.
   Сжатые GPU-текстуры (KTX2/Basis) — только если всё остальное не помогло, отдельной задачей.
5. Флаг `--disable-gpu-compositing` и прочие хаки Chromium не использовать без необходимости. Если что-то нужно для Intel iGPU на Windows — задокументировать.

## Выходы
Правки `electron-builder.yml`, `src/render/AtlasLoader.ts`, `PerfOverlay`, отчёт с замерами.

## Критерии приёмки
- [ ] Бюджеты `05` §9 по памяти и FPS выполнены на обеих машинах (или получено разрешение пользователя, если Windows-ноутбук недоступен для замера — тогда замер на Mac с тиром 2x и перенос выводов).
- [ ] `npm run check` зелёный. Коммит `T4.4: tiers and memory`.
